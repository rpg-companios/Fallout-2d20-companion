# Тесты работы с аватарами персонажей

Этот каталог содержит тесты для функциональности работы с кастомными изображениями персонажей.

## Структура тестов

### 1. `character-avatar.test.js`
**Тип:** Unit-тесты  
**Цель:** Тестирование доменных функций из `domain/characterAvatar.js`  
**Покрытие:**
- Лимиты аватаров (AVATAR_LIMITS)
- Валидация data URL (validateAvatarDataUrl)
- Метаданные аватара (buildAvatarMetadata)
- Расширения файлов (getFileExtension)
- Схема БД (character_avatars таблица)

### 2. `character-image-logic.test.js`
**Тип:** Unit-тесты  
**Цель:** Тестирование логики работы с изображениями  
**Покрытие:**
- Валидация всех поддерживаемых форматов (JPEG, PNG, GIF, WebP, BMP, SVG)
- Проверка размера изображений
- Определение расширений для неизвестных MIME-типов
- Расчет размера base64

### 3. `character-image-picker.test.js`
**Тип:** Интеграционные тесты (требует React Testing Library)  
**Цель:** Тестирование хука `useCharacterImage`  
**Покрытие:**
- Выбор изображения из галереи
- Проверка разрешений
- Сжатие и сохранение изображения
- Обработка ошибок (отмена, превышение размера)
- Поддержка разных форматов

### 4. `use-character-image-hook.test.js`
**Тип:** Интеграционные тесты  
**Цель:** Тестирование состояния хука  
**Покрытие:**
- **imageVersion** увеличивается после успешного сохранения
- **imageVersion** НЕ увеличивается при отмене
- **imageVersion** НЕ увеличивается при отсутствии разрешений
- **imageVersion** НЕ увеличивается при превышении размера
- **isLoading** меняется во время обработки

### 5. `image-section-component.test.js`
**Тип:** Тесты компонентов (требует React Testing Library)  
**Цель:** Тестирование компонента `ImageSection`  
**Покрытие:**
- Загрузка изображения при монтировании
- Перезагрузка изображения при изменении `imageVersion`
- Перезагрузка изображения при изменении `characterId`
- Перезагрузка изображения при изменении `getCharacterImageUrl`
- Нет загрузки при отсутствии `characterId`
- Нет загрузки при отсутствии `getCharacterImageUrl`

### 6. `character-image-integration.test.js`
**Тип:** Интеграционные тесты  
**Цель:** Полный user flow  
**Покрытие:**
- Выбор изображения → сохранение → обновление UI
- Обновление аватара после выбора
- Отмена выбора изображения
- Отмена подтверждения выбора

## Как запускать тесты

### С vitest (рекомендуется)
```bash
# Установить зависимости
pnpm install

# Запустить все тесты
npm test

# Запустить только тесты аватаров
npm test -- --run __tests__/avatar/
```

### Без vitest (с помощью Node.js)
```bash
# Запустить скрипт тестирования
node run-avatar-tests.js
```

Этот скрипт проверяет:
- Все функции валидации и утилиты
- Статическую структуру хуков
- Наличие необходимых функций и состояний

## Какие баги ловятся тестами

### ✅ Ловятся:
1. **Неправильная валидация форматов** - если `validateAvatarDataUrl` отбрасывает валидные форматы
2. **Неправильное определение расширений** - если `getFileExtension` возвращает неверные значения
3. **Ошибки в ограничениях** - если `AVATAR_LIMITS` имеет неверные значения
4. **Отсутствие imageVersion** - если хук не обновляет состояние после сохранения
5. **Неправильные вызовы функций** - если используются несуществующие функции (например, `saveAvatarCache` вместо `setAvatarCache`)
6. **Неправильный синтаксис вызовов** - если `showRawAlert` вызывается с позиционными аргументами вместо объекта

### ⚠️ Не ловятся unit-тестами (требуют интеграционные тесты):
1. **Проблемы с рендерингом UI** - требуют тесты компонентов
2. **Взаимодействие между компонентами** - требуют интеграционные тесты
3. **Проблемы с React состоянием** - требуют тесты с рендерингом

## Рекомендации

1. **Добавляйте интеграционные тесты** для сложных сценариев
2. **Тестируйте UI поведение** с помощью React Testing Library
3. **Проверяйте edge cases**:
   - Пустые значения
   - Null/undefined
   - Очень большие файлы
   - Нестандартные форматы
4. **Запускайте тесты перед коммитом**

## Пример добавления нового теста

```javascript
// __tests__/avatar/new-feature.test.js
import { describe, it, expect } from 'vitest';
import { newFunction } from '../../domain/newModule';

describe('newFeature', () => {
  it('should do something', () => {
    const result = newFunction('input');
    expect(result).toBe('expected');
  });
});
```
