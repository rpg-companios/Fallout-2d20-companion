# Установка патча 550: нехватка заколок — стоп

Патч подготовлен от состояния **версии 549**. Файл установки:
`patchs/550-pin-spend-stop.patch`.

> **Слово владельца:** «при нехватке заколок — стоп. Одна заколка = одна заколка».

Это ответ на открытый вопрос, который нашла поведенческая приёмка патча 549.
Правило 5 устава движка: **отказ не трогает баланс**.

## Что было не так

Приёмка 549 сравнила два пути изменения листа и обнаружила спорное поведение:

1. `store.spendItemStacks` отказывал честно — `{ ok: false, reason: 'not-enough-items' }`,
   баланс не тронут;
2. но `spendBobbyPins` после отказа шёл в легаси-резерв
   `engine.consumeBobbyPins`, а тот списывал **сколько было**: при 1 заколке и
   запросе на 3 исчезала одна, баланс становился 0.

Оба пути — рука игрока и команда Мастера — вели себя одинаково, поэтому закон
равенства 549 не был нарушен. Дефект был в самом правиле расхода, и патч 549 его
не менял, вынеся вопрос владельцу. Владелец решил: **стоп**.

## Что меняется

| Файл | Что сделано |
| --- | --- |
| `server/lockPicking.js` | `consumeBobbyPins` стал атомарным: если запрошено больше, чем есть, возвращается `consumed: 0`, признак `refused: 'not-enough-pins'` и **нетронутая копия** снимка; исходник по-прежнему не мутируется |
| `components/lootTrade/spendBobbyPins.js` | запас проверяется общим каноном `countBobbyPins` **до любой мутации**; при нехватке — возврат 0 без изменения стора, без `saveCharacter` и без публикации в комнату; легаси-путь использует тот же атомарный канон |
| `__tests__/room/pin-spend-all-or-nothing-550.test.js` | приёмка (15) |
| `__tests__/room/gm-player-parity-549.test.js` | проверка нехватки обновлена под новое правило: ноль списаний, заколка цела |
| `docs/gm-player-parity-law.md` | §5 переписан: открытый вопрос снят, зафиксировано правило владельца |
| `docs/agents/state.md` | запись 550, вопрос убран из «Открытых вопросов» |
| `docs/roadmap.md`, `docs/changelog.*.md`, `public/version.json`, `patchs/baseline.json` | версия/отсечка 550, тезис 40 |

## Поведение после патча

| Ситуация | Было | Стало |
| --- | --- | --- |
| 1 заколка, запрос 3 | списана 1, осталось 0 | списано 0, осталась 1 |
| 3 заколки, запрос 3 | списано 3 | списано 3 (без изменений) |
| 2 заколки в легаси-форме, запрос 3 | списано 2 | списано 0 |
| 5 заколок, запрос 2 | списано 2 | списано 2 (без изменений) |
| 0 заколок, запрос 1 | отказ | отказ (без изменений) |
| запрос 0 или отрицательный | пустой вызов | пустой вызов (без изменений) |

При отказе лист **не сохраняется и не публикуется** — комната не получает ложного
обновления, повтор команды ничего не портит.

## Границы

- Мини-игра замка не менялась: без заколок доска уже уходила в `awaitingRetry`
  с `OUT OF PINS`, `pinActive: false`, а нажатие отвергалось. Это закреплено тестом.
- Правило 522 сохранено: надетое и запертое не расходуется, поля предметов не
  обрезаются (`name`, `condition` остаются).
- Закон снимка 529 не тронут: сервер по-прежнему не правит лист, а шлёт команду.
- Закон равенства 549 сохранён и проверен: рука игрока и команда Мастера дают
  одинаковый результат и при отказе, и при успехе.
- Канон поиска заколок общий (`countBobbyPins`): поддержаны каноническая форма
  `weaponId` и легаси `catalogId`/`itemId`/`code`, словари и массивы, дубликаты
  одного экземпляра в `items` и `equipment.items`.

## Установка через консоль

```bash
git fetch --no-tags origin arena/f90c80d8-fallout-2d20-companion
git show FETCH_HEAD:apply-patch.sh > apply-patch.sh
chmod +x apply-patch.sh
./apply-patch.sh 550
```

**Сервер комнат обновлять нужно**, если он крутит `server/lockPicking.js`: канон
`consumeBobbyPins` изменился. Клиент самодостаточен — ранняя проверка запаса
работает и со старым сервером, потому что списание всегда исполняет клиент.
