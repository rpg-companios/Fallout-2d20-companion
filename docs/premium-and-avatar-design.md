# Дизайн: аватар рядом с сейвом + премиум-доступ на Google-аккаунте

**Статус:** предложение (этап 0). Ничего не реализовано — это фиксация решений
до написания кода. Владелец вправе поменять любой пункт.

Контекст: аватар персонажа — будущая **премиум-фича**. Хранить его нужно
**не в сейве, а рядом с ним**: аватар меняется редко, гонять его на каждом
автосейве незачем; проверять — только в моменты полной синхронизации
(ручной синк / первая загрузка персонажа на новом устройстве).

---

## Часть 1. Аватар

### 1.1 Размещение

**Google Drive** (тот же `appDataFolder`, та же папка сеттинга):

```
appDataFolder/
  fallout/
    <id>__<имя>.json      ← сейв (как сейчас, без изменений)
    avatars/
      <characterId>.jpg   ← аватар (новое)
```

- Имя файла — по **стабильному id персонажа** (`characterId`), не по имени:
  переименование персонажа не трогает аватар, ничего не осиротевает.
- Удаление персонажа → при полном синке удалить и его аватар из Drive.

**Локально (копия на устройстве)** — таблица в существующей БД
(`db/schema.js`, web — IndexedDB, native — SQLite):

```sql
CREATE TABLE IF NOT EXISTS character_avatars (
  character_id TEXT PRIMARY KEY,
  data_url     TEXT NOT NULL,   -- JPEG data URL (~50–150 КБ)
  md5          TEXT NOT NULL,   -- контрольная сумма для сравнения с Drive
  updated_at   INTEGER NOT NULL
);
```

**В сейве JSON** — только метаданные, не фото (~100 байт):

```json
"avatar": { "md5": "…", "updatedAt": 1694000000000 }
```

### 1.2 Протокол синка (редкого)

Точки, где аватар вообще проверяется:

1. **Полная синхронизация** (кнопка «Синхронизировать с Google Drive») —
   выгрузка/загрузка аватаров всех персонажей.
2. **Первая загрузка персонажа** на устройстве (в списке персонажей его
   аватара нет в локальном кэше).

**Автосейв аватар не трогает** — он продолжает гонять только лёгкий JSON.

Правила (для каждого персонажа):

| Ситуация | Действие |
|---|---|
| Локально есть, в Drive файла нет | upload `avatars/<id>.jpg` |
| Локально есть, `md5` (Drive `md5Checksum`) отличается | младший по `updatedAt` проигрывает (last-write-wins, как у сейвов) |
| Локально нет, в Drive есть | download → кэш в `character_avatars` |
| Обе стороны совпадают по `md5` | ноль запросов (сравнение по метаданным Drive, без скачивания) |
| Персонаж удалён локально, аватар остался в Drive | удалить аватар |

`md5Checksum` — штатное поле метаданных файла Drive: сравнение без скачивания.

### 1.3 Выбор и показ фото

- `expo-image-picker` (галерея; камера — опционально) + плагин в `app.json`.
- `expo-image-manipulator`: JPEG **512 px, качество ~0.7** → 50–150 КБ.
- Жёсткий лимит на сохранение: **300 КБ** (защита от «сырого» фото).
- Кнопка на фото в экране характеристик; превью — всегда из локального кэша
  (оффлайн-дружелюбно: пока синка не было, фото просто нет).

### 1.4 Почему не в сейве (фиксация решения)

1. Сейв остаётся лёгким: автосейв не гоняет +100 КБ на каждое изменение.
2. У аватара свой, редкий цикл синка — ровно как просил владелец.
3. Чистое отделение будущей премиум-фичи: включение/выключение премии
   не влияет на формат сейвов вообще.

## Часть 2. Премиум-доступ на базе Google-аккаунта

### 2.1 Идентичность

Используем **тот же Google Identity Services**, что уже работает для Drive
(`components/cloudSync/googleDriveSync.js`, `initTokenClient`). Для получения
стабильного идентификатора аккаунта добавляется scope `openid` (или GIS
Sign-In / One Tap): даёт `sub` — неизменный id аккаунта Google — и `email`.

Один Google-аккаунт = одно право на всех устройствах пользователя: после
входа право подтягивается само.

### 2.2 Три варианта хранения права (выбирает владелец)

**В1. Файл-лицензия в `appDataFolder`** (`premium.json`).

- Плюс: ноль инфраструктуры; файл виден всем устройствам юзера.
- Минус: `client_id` публичен (зашит в приложение), технически поддаётся
  подделке подготовленным человеком. Уровень — «честная система».

**В2. Оффлайн-ключи с подписью Ed25519 (рекомендация).**

- Лицензия — компактный токен, подписанный **приватным ключом владельца**;
  в приложении зашит только **публичный** ключ. Подделать без приватного
  ключа нельзя.
- Содержимое: `{ subHash, plan, features[], exp, iat, keyId }`, где `subHash` —
  хеш `sub` Google-аккаунта (привязка: ключ работает только с этим аккаунтом).
- Проверка полностью офлайн; перевыпуск/продление — новый ключ (по e-mail
  или файлом в Drive при синке).
- Плюс: нет сервера, нет домена, нет поддержки. Минус: нет мгновенного
  отзыва (решается коротким `exp` + перевыпуском).

**В3. Бэкенд** (Cloud Run/Functions + Firestore + вебхуки платёжки).

- Полный контроль: отзыв, смена плана, аналитика, семейный доступ.
- Минус: сервер, домен, поддержка; для РФ-аудитории платёжная часть —
  отдельная тема: **Google Play Billing в РФ недоступен**, работают
  ЮKassa / CloudPayments / Robokassa (подключаются вебхуками именно к В3).

**Рекомендация:** интерфейс `EntitlementProvider` с реализацией В2 сейчас и
заложенной возможностью В3 потом — клиент при этом не переписывается.

### 2.3 Клиентская архитектура

- `domain/premium.js` (**движок**, не модуль сеттинга):
  - `FEATURE_REGISTRY` — реестр фич (`{ id, premium: true|false, moduleId? }`);
    модули сеттингов регистрируют свои фички сами (мульти-сеттинг);
  - `isFeatureAvailable(featureId)` — единая точка проверки для UI;
  - `getEntitlement()` / `refreshEntitlement()` — кэш права с TTL 14–30 дней,
    офлайн-проверка без сети.
- **Железное правило данных:** окончание премиума **никогда не удаляет
  данные пользователя**. Аватар остаётся видимым — блокируется только
  возможность *сменить* фото. То же для всех будущих премиум-фич.
- UI: замочки на премиум-элементах, экран «О премиуме», вход — та же
  Google-кнопка, что у синка.
- Честная граница: в офлайн-приложении проверка всегда клиентская и в
  принципе обходится патчем клиента; серверная защита имеет смысл только
  для фич, живущих на сервере. Для companion-приложения уровень В2 —
  осознанный и достаточный.

### 2.4 Этапы

| Этап | Что делаем | Премиум-статус аватара |
|---|---|---|
| 0 | этот документ | — |
| 1 | аватар целиком (пикер, сжатие, кэш, редкий синк) | бесплатно для всех (`isFeatureAvailable` уже стоит на месте и возвращает true) |
| 2 | скелет премиума: `domain/premium.js`, провайдер В2, замочки, экран | аватар объявлен премиум-фичей, но право выдаётся всем (open beta) |
| 3 | платежи + включение платности | аватар — премиум |

Так аватар обкатывается массово до монетизации, а включение платности
становится переключением реестра фич, не авралом с кодом.

## Открытые вопросы (решает владелец)

1. Платёжный провайдер и аудитория: только РФ (ЮKassa/CloudPayments) /
   международка (Paddle/LemonSqueezy — Stripe из РФ недоступен) / оба.
2. Вариант права: В2 (ключи, без сервера) — рекомендация — или сразу В3.
3. Цены и состав тиров (например: Free / Premium разовый / Premium-год).
