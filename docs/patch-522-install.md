# Установка патча 522: один предмет на всех экранах

Патч подготовлен от состояния **версии 521** (коммит `76fd1e7`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–522
цепочкой.

> Владелец: «Ограничений на вес и количество нет, предмет из инвентаря =
> предмету на складе. Если оружие с модами, то оно с теми же модами, состоянием,
> на складе. Если в инвентаре 2 предмета с разными зарядами, то они и на складе
> с разными. Предметы не должны терять свойства при смене места хранения. То же
> самое с торговцами. Если я торговцу дал модифицированное оружие, то оно таким
> и числится и цена и вес считаются от модов. Механики инвентаря в доменный
> модуль. Чтобы использовали все. перестать обрезать поля. У торговцев считать
> цену с модами. Сделай.»
>
> И отдельно: «Защита сервера это святое. Безопасность важна.»

## Что изменено

### 1. Игровые лимиты склада отменены

Удалены 200 строк на складе, 999 предметов в стопке, 999 предметов за операцию,
код `STORAGE_FULL` и парная строка «хранилище заполнено». Теперь можно положить
сколько угодно вещей и каким угодно количеством за один перенос.

**Защита сервера не ослаблена** — она усилена:

| Предохранитель | Состояние |
| --- | --- |
| `LIMITS.MAX_MESSAGE_BYTES` (2 МБ на WebSocket-сообщение) | без изменений |
| Число операций в одном сообщении (50) | без изменений, это защита протокола, не лимит игры |
| Целое положительное количество, `Number.isSafeInteger` | без изменений |
| Санитайзинг снимка: `__proto__` / `constructor` / `prototype`, циклы, глубина, 64 КБ | **добавлено** |
| Валидация импорта снимка (`entries` должен быть массивом) | **добавлено** |
| Роли, членство, владелец, атомарность переноса | без изменений |

### 2. Один доменный модуль на троих

Канон — `server/itemStacking.js`, клиентская точка входа —
`domain/itemStacking.js` (`module.exports = require(...)`). Такое расположение
необходимо: лёгкий деплой NetAngels копирует в `app/` только `server/` + `ws`,
поэтому сервер не может зависеть от каталога `domain/`. Дубля правил нет.

Потребители одного модуля:

- `components/screens/InventoryScreen/InventoryScreen.js` — локальный дубль
  `getStackKey` удалён, инвентарь берёт `itemStacking.itemStackKey`;
- `server/partyStorageRules.js` — `storageStackKey` и `applyStorageDeposits`
  по общему ключу;
- `server/lootTradeSession.js` и `domain/lootTrade.js` — прежние два
  `snapshotMergeSignature` стали тонкими обёртками над `itemStackKey`;
- `components/lootTrade/PartyStorageModal.js`,
  `src/lootTrade/grantCharacterItems.js`,
  `components/lootTrade/PlayerLootTradeOverlay.js` и
  `ContainerItemConfigModal.js` — снимок и эффективные числа через общий модуль.

Разные `appliedMods`, `charges`, `durability`, `hpCurrent`, `uniqQualities` и
`baseName` дают разные стопки везде; `uniqueId`, `equipInstanceId`, `stackKey`,
`equipped`, `locked`, `quantity` на идентичность не влияют. Ключевые записи
по-прежнему не стакаются.

### 3. Поля больше не обрезаются

`itemTransferSnapshot` сохраняет предмет целиком и меняет только `quantity`
(количество едет отдельным полем операции), `equipped` и `locked`. Удалены
деструктуризация с выбросом `appliedMods` в окне склада и
`delete cleanSnapshot.uniqueId` при продаже торговцу.

### 4. Цена и вес считаются с модов

`resolveItem` уже обогащает Weapons через `domain/enrichItem.js`, складывая
`mod.cost` и `mod.weight`. Теперь продажа игрока и карточка товара берут
`getItemPrice(resolved)` / `getItemWeight(resolved)`, а не голую каталожную
`catalogEntry.cost`. Эффективные `cost`/`weight` кладутся в `itemSnapshot`,
переживают серверную нормализацию (`normalizeSessionItem`,
`normalizeContainerItem`) и читаются формулами скупки через
`itemStacking.effectiveItemCost`. Модифицированное оружие больше не
обесценивается при смене владельца.

### 5. Окно склада не менялось

Две панели, буфер, «Перенести», локальные колбэки вноса/выдачи. Без цен,
наценок, крышек, настроек, применения и экипировки. Ключи — только чтение;
Мастер транслирует записи, видит «Выдать на склад» и не может брать вещи;
экспорт/импорт файла работает у Мастера и игрока.

## Проверка

```bash
./apply-patch.sh            # или ./apply-patch.sh --status
cat public/version.json     # "version": "522"
npm run typecheck
npm test
npm run build
npm run serve:app           # перезапустить комнатный сервер (менялся server/)
```

Приёмочные тесты: `__tests__/room/item-stacking-522.test.js` и обновлённый
`__tests__/room/storage-polish-521.test.js`. Проверяются: единый ключ стаканья,
сохранность полей, отсутствие лимитов, эффективная цена с модами, неизменность
двухпанельного окна и вся серверная защита.

`patchs/baseline.json` = `522`, заметки релиза парные (89 / 89), `dist/`
пересобран. Живой план — `docs/roadmap.md`: тезис 12 закрыт полностью,
следующий этап — иерархия пространств и доступ (тезис 13).

## Важно

Мини-игры, ворота, ключи и вложенность локаций **не менялись**. Все уточнения
владельца по иерархии перенесены в следующий этап и в код не попали.
