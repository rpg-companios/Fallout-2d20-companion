# Стартовая карта ИИ-агента

> Назначение: агент, открывший репозиторий, смотрит СЮДА первым делом —
> чтобы понять, как приложение работает, и править 1–2 файла вместо
> чтения всего стека. Карта содержит только проверенные факты; дополняется
> при каждом переезде. Дата ревизии: 2026-09-22 (патч 312).

## Порядок чтения (обязательный минимум)

1. `replit.md` — что за программа, стек, структура папок.
2. `docs/architecture/engine-dna.md` — главный контракт: движок не знает
   сеттинг; TS для новых контрактов; один владелец правила; миграции —
   единственная граница legacy.
3. `docs/architecture/engine-charter.md` — устав: один шаг = один патч,
   паспорта стора/сейва, политика тестов, протокол отчёта об ошибке.
4. `setting-contract.md` — контракт пакета сеттинга (`.trpg`).
5. `docs/agents/data-flows.md` — потоки данных по ключевым механикам
   (каталог, моды оружия, робо-слоты, сейвы, выживание).

## Карта репозитория по слоям

| Слой | Где | Что там |
|---|---|---|
| Точка входа | `App.js`, `index.js` | навигация, инициализация БД, автосейв-таймер |
| Движок (контракты) | `src/engine/` | контракты выводимости (`contracts/`), реестр (`derivations/`), моды предметов (`items/weaponMods.ts` — единая правда модов и план записи) |
| Движок (состояние) | `src/store/` | `characterStore.js` (всё состояние персонажа), паспорта `characterState.ts`/`saveSnapshot.ts`/`characterActions.ts`, `saveSchema.js` (версия сейва), `migrations.js` (НЕ трогать задним числом) |
| Сейвы | `src/saves/characterSaves.js` | снапшот/загрузка/список; база — `db/` |
| База/каталог | `db/` | `catalogSource.js` — строки каталога из JSON (перки — через дверь сеттинга); SQLite — состояние, не каталог |
| Универсальный домен | `domain/` | броски, счётчики, миграции форм, `robotSlots.js` (слоты роботов), `enrichItem.js` (конвейер модов), `registry.js` (единая точка чтения данных) |
| Сеттинг Fallout | `modules/fallout/` | данные (`data/`), i18n (`i18n/`), экраны (`screens/`), выживание (`survival/`), формулы модуля (`weapons/weaponAmmoSpend.js`), дверь — `modules/fallout/index.js` (экспорт `SETTING`) |
| Движковые экраны | `components/` | инвентарь (`InventoryScreen/`), менеджер героев |
| Тесты | `__tests__/` | предохранители живут всегда; сюит зелёный = патч готов |

## Типовая задача → какие файлы править

| Задача | Файлы |
|---|---|
| Добавить мод оружия людей | `modules/fallout/data/equipment/weapon_mods.json` + i18n-зеркало `modules/fallout/i18n/<ru-RU,en-EN>/data/equipment/weapon_mods.json` |
| Добавить мод робо-оружия | `modules/fallout/data/equipment/robot/weapon_mods.json` + i18n; мод ОБЯЗАН заявить `slot` и `applies_to_ids` (слоты робо-оружия выводятся из модов) |
| Связать робо-оружие с людской базой | поле `trueItemId` в `robot/weapons.json` — ПОЛНЫЙ вариант: боевых полей в робо-записи быть не должно, статы/эффекты/моды едут от людской базы |
| Оружие «с модом из коробки» | поле `modIds` в записи оружия (`robot/weapons.json`); конвенция китов: `weaponId` + `modIds` |
| Новое качество расхода зарядов | читатель в `modules/fallout/weapons/weaponAmmoSpend.js` + ключ i18n `weapon.ammoSpend.source.<source>` (ru+en) |
| Добавить предмет/броню/расходник | соответствующий JSON в `modules/fallout/data/equipment/` + i18n-зеркало |
| Экран сеттинга | `modules/fallout/screens/<Screen>/` — экраны НЕ импортируют данные напрямую, только через реестр/каталог |
| Новое поле состояния стора | паспорт `src/store/characterState.ts` В ТОМ ЖЕ ПАТЧЕ (тест `data-passports` упадёт иначе) |
| Новый формат сейва | версия в `src/store/saveSchema.js` + миграция в конец цепочки `migrations.js` |
| Универсальная механика | `domain/` (JS) или `src/engine/` (TS для новых контрактов); сеттинг подставляет данные через реестр |

## Правила, которые нельзя нарушать (короткий список)

- Движок не импортирует `modules/...` — граница проверяется тестом
  `__tests__/settings/settings-boundary.test.js`.
- Каталог — JSON сеттинга; DB хранит состояние. Двух копий каталога не
  заводить; поиск предмета — один (`domain/resolveItem.js`).
- Одна операция = один action; модалка показывает/спрашивает/сообщает,
  но не считает правила.
- Установщик патчей: истина — в содержимом файлов (`./apply-patch.sh N`,
  `--status`); правки в рабочем дереве коммитить до применения цепочки.
