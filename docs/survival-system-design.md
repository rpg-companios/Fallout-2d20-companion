# Дизайн системы выживания (еда / вода / усталость)

**Статус:** черновик 0.2 для согласования — не реализовано.

**Дата редакции:** 2026-09-07 (актуализирует черновик 0.1 от 2026-08-17).

**Область:** экран экипировки (поле «Эффекты» и новое поле «Выживание»),
инвентарь, отдых, настройки, заболевания, временные таймеры.

> Правило документа: фиксируются **только** решения владельца и факты
> кодовой базы. Неизвестное — в открытые вопросы. Ничего не додумывается.

---

## 0. Решения владельца (2026-09-07)

1. **Место:** экран экипировки. Рядом с уже существующим полем «Эффекты»
   появляется отдельное поле выживания.
2. **Вид:** три **вертикальные** разноцветные шкалы, каждая разделена на
   **5 секций**. Секция 5 (верхняя) — условно «превосходно», секция 1 (нижняя) —
   «персонажу очень плохо». **Названия ступеней пока не даются.**
3. **Подписи шкал** (внизу каждой): «еда», «вода», «усталость» —
   **иконками**: еда — мясо, вода — капля, усталость — 💤.
4. **Кому доступны:** только людям, мутантам и гулям. **Роботы и киборги
   лишены шкал** (поле не показывается вовсе).
5. **Настройки:** интервал шага по времени — через сколько (игрового) времени
   происходит спуск на 1 деление; либо полное **отключение системы**.
6. **Кнопки под шкалами** — по одной на шкалу, открывают **модалки**:
   - еда — только предметы инвентаря категорий **еда / дикоросы**;
   - вода — только предметы категории **напитки**;
   - «Спать» — выбор, **где** спит персонаж: в кровати или в пустоши.
7. **Сон в пустоши** — **проверка на болезнь**.
8. **Длительность сна:** выбирается от **1 до 24 часов** — вне зависимости
   от места сна. Часы сна **продвигают длительность препаратов и других
   временных таймеров**.
9. **Качество еды и напитков влияет на подъём шкалы.** Примеры владельца:
   грязная вода насыщает **в 3 раза хуже** чистой; сырая еда хуже готовой.
   Точная таблица множителей — открытый вопрос (§12).

## 1. Цель

Три независимые шкалы состояния персонажа (сытость, гидратация, отдых),
которые:

- видны в одном месте на экране экипировки;
- меняются от игрового времени (спуск) и действий игрока
  (поесть / попить / поспать);
- хранятся в сейве персонажа как единственные источники истины;
- не являются обычными временными эффектами и не попадают в
  `activeTimedEffects`;
- доступны только типам персонажей, которым система положена (§4).

## 3. Размещение в интерфейсе

Экран экипировки, рядом с полем «Эффекты» — новое поле «Выживание».

Предварительный макет (структура, не финальные цвета/размеры):

```text
┌─ Выживание ───────────────────────────┐
│   ▲5   ▲5   ▲5     ← секция 5:        │
│   ██   ██   ██        «превосходно»   │
│   ▒4   ▒4   ▒4                        │
│   ▓3   ▓3   ▓3                        │
│   ░2   ░2   ░2                        │
│   ▒1   ▒1   ▒1     ← секция 1:        │
│   ▁    ▁    ▁        «очень плохо»    │
│  🍖   💧   💤      ← подписи-иконки    │
│                                      │
│  [ Еда ]  [ Вода ]  [ Спать ]        │
└──────────────────────────────────────┘
```

Правила отображения:

- шкалы вертикальные, заполнение снизу вверх, текущая секция выделена
  цветом своей шкалы (три разные цветовые гаммы);
- секции 1–5 пронумерованы в данных, но **без названий** (решение §0.2);
- подписи шкал — иконки: мясо, капля, 💤 (векторная иконка набора или
  эмодзи — выбор реализации; текстовые подписи остаются в a11y-атрибутах,
  локализованные);
- кнопки — под шкалами, по одной на шкалу;
- у `robot`/`cyborg` поле скрыто целиком (не «серым», а отсутствует);
- при выключенной системе (§6) поле скрыто для всех.

Требует решения владельца: цвета гамм; показывать ли подпись «Выживание»
у поля; поведение на узких экранах.

## 4. Типы персонажей

| `characterType` | Шкалы | Основание |
|---|---|---|
| `human`, `ghoul`, `mutant` | есть | решение владельца §0.4 |
| `robot`, `cyborg` | нет, поле скрыто | решение владельца §0.4 |

Проверка — по `origin.characterType` (тот же источник, что и `isRobotCharacter`).
Гули/мутанты получают систему наравне с людьми; особенности их метаболизма
(если появятся в книгах) — через модификаторы скорости (§11), не через
отключение системы.

## 5. Модель состояния

```text
survival: {
  food:      1..5,   // текущая секция шкалы еды
  water:     1..5,   // шкала воды
  fatigue:   1..5,   // шкала усталости (5 — бодр)
}
```

- хранится в сейве персонажа (новая версия схемы + миграция: всем
  подходящим типам — начальная секция, неподходящим — отсутствие поля);
- участвует в экспорте/импорте, дублировании, облачном синке;
- ступень — единственный источник истины: ни названий, ни штрафов в сейве;
- в `activeTimedEffects` не попадает никогда.

Начальная секция для новых персонажей и при миграции старых сейвов —
открытый вопрос (предложение по умолчанию: 5/5/5, решает владелец).

## 6. Настройки

Живут в существующем разделе «Настройки режима „Выживание“»
(`sectionKey: survivalMode`), `controlSurface: settings`:

| id (предварительно) | тип | смысл |
|---|---|---|
| `survivalModeEnabled` | boolean | система целиком вкл/выкл (выкл = поле скрыто, состояние сохраняется в сейве) |
| `survivalStepHours` | number | через сколько **игровых часов** спуск на 1 деление |

Открытые вопросы: один интервал на все шкалы или три отдельных;
диапазон и шаг выбора (например 1–12 ч); значение по умолчанию;
единица «часы игрового времени» — как соотносится со сценами (§10).
i18n — ru и en одновременно, по канону проекта.

## 7. Сценарий «Еда»

1. Кнопка под шкалой еды → модалка.
2. Модалка показывает **только** предметы инвентаря категорий
   **еда / дикоросы** (фильтрация по данным предмета, не по тексту названия).
3. Выбор предмета → применение к себе (существующая механика применения
   расходников: радиация, эффекты, `sceneRiskEvents`) **плюс** подъём шкалы
   еды на величину, зависящую от качества (§0.9, таблица §12).
4. Предмет уходит из инвентаря по штатным правилам.

Нюанс данных: в `food.json` нет отдельного признака «дикоросы» — все 75
записей `itemType: "food"`. Нужен признак или список (открытый вопрос §12).

## 8. Сценарий «Вода»

Аналогично §7, модалка показывает категорию **напитки** (`itemType:
"drinks"`). Качество: `irradiated`/тип воды уже в данных; множитель
«грязная = 1/3 чистой» — из решения владельца, точная таблица §12.

## 9. Сценарий «Спать»

Модалка с двумя независимыми выборами:

1. **Где:** кровать / пустошь.
   - Пустошь → после сна **проверка на болезнь** (машина
     `sceneRiskChecks`/`diseaseExposure` + `rollDiseaseFromCatalog`;
     точное правило — какая сложность/шанс — открытый вопрос).
   - Кровать → без проверки.
2. **Сколько часов:** 1–24 (таймер 1–24, шаг 1).

Результаты сна:

- усталость: подъём шкалы (величина/кап — открытый вопрос; предложение:
  часы напрямую конвертируются интервалом из §6);
- **часы сна продвигают все временные таймеры**: длительность препаратов,
  временные эффекты, окна доз — конвертация «часы → сцены/минуты» (§10);
- еда/вода за время сна **спускаются** по тому же интервалу §6
  (спит 8 часов → минус столько делений, сколько накопит интервал) —
  предложение, требует подтверждения владельца;
- где именно «кровать» — просто выбор в модалке; поиск предмета-кровати
  в инвентаре/окружении в первой версии не делается.

## 10. Время и переходы

Источник игрового времени — главный открытый вопрос системы:

- сейчас приложение не имеет глобальных игровых часов;
- таймеры эффектов живут в сценах/минутах (`SCENE_RULES`),
  окно доз препаратов — в реальном времени устройства;
- сон задаёт время явно («прошло N часов») — это первый источник;
- остальные источники (кнопка «прошла сцена/час», путешествие, реальное
  время) — решает владелец; реальное время без решения не используется.

Для продвижения таймеров часами нужна утверждённая конвертация
(сколько минут в сцене — в правилах игры; предложение: 1 сцена = 10 мин
или значение из книги, решает владелец).

## 11. Последствия ступеней

Механические эффекты секций (штрафы на броски, скорость и т.п.) —
**не определены владельцем**. Правила прежние: структурированные данные
модуля, универсальный обработчик движка, смена ступени пересчитывает
последствия, ничего не угадываем по текстам. Шаблон-таблица — как в
редакции 0.1, заполняется после решения.

## 12. Еда и напитки: качество и насыщение

Решение владельца: качество влияет на подъём шкалы. Примеры: грязная вода
×1/3 чистой; сырая еда хуже готовой. Признаки качества уже в данных
(`state`/`rawMeat`/`preserved`, `irradiated`, конкретные id вод).

Открытая таблица (заполняет владелец):

| Категория | Признак в данных | Подъём шкалы |
|---|---|---|
| Чистая вода | `drink_purified_water` и др. (`irradiated: false`) | ? |
| Грязная вода | `drink_dirty_water` (`irradiated: true`) | ×1/3 от чистой (пример владельца) |
| Готовая еда | `state != "raw"` / не `rawMeat` | ? |
| Сырое мясо | `rawMeat: true` | хуже готовой — во сколько? |
| Консервы | `preserved: true` | ? |
| Дикоросы | признака нет — нужен список/поле | ? |
| Алкоголь | `isAlcohol: true` | влияет на воду вообще? |

Также открыто: подъём в «делениях» или в промежуточных единицах внутри
секции; кап за один приём; можно ли есть при полной шкале.

## 13. Болезни, черты, исключения

Сон в пустоши использует существующую машину болезней. Модификаторы
скорости шкал от болезней/черт (ускорение голода при болезни, иммунитеты
гулей и т.п.) — структурированными данными, когда владелец их задаст;
поведение по текстам описаний не угадывается.

## 14. Разделение движка и модуля

Прежний принцип сохраняется: **контент — в сеттинге, логика — в движке**.

- Движок: модель шкал (1..5), шаг по времени, поле UI с вертикальными
  шкалами и кнопками, модалки-фильтры, продвижение таймеров часами,
  применение множителей качества.
- Модуль Fallout: какие `characterType` участвуют, категории предметов
  (еда/дикоросы/напитки), таблица качества/насыщения, правило болезни
  в пустоши, названия ступеней (когда появятся), настройки в
  `sectionKey: survivalMode`.
- Движок не содержит слов «голод/жажда» как обязательной механики:
  шкалы описываются данными (id, иконка, категория кнопки).

## 15. Локализация и иконки

- Подписи шкал — иконки (мясо, капля, 💤); текст — только в a11y и в
  настройках, ru + en одновременно.
- Названия секций 1–5 — после решения владельца, сразу в двух языках.
- Кнопки: «Еда» / «Вода» / «Спать» — локализуемые ключи (иконки +
  текст/только иконки — решает владелец).

## 16. Проверки будущей реализации

- шкалы появляются только у `human/ghoul/mutant` и только при включённой
  системе;
- выключение настройки не удаляет состояние из сейва;
- модалки показывают только разрешённые категории;
- применение еды/воды поднимает шкалу по таблице качества, предмет
  расходуется;
- сон: часы 1–24, пустошь → проверка болезни, таймеры препаратов
  продвинулись на верное число сцен/минут;
- состояние переживает save/load, экспорт/импорт, дубль, облачный синк;
- миграция старых сейвов проставляет начальные секции;
- i18n parity ru/en с первого дня.
