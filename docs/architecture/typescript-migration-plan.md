**Связанные документы:** `docs/architecture/engine-charter.md` (устав, §2 цикл

## Решения владельца (2026-09-18, в этой редакции)

1. **Цель TypeScript — ловить ошибки ДО старта приложения**, а не разбирать
   падения в браузере. Вся серия подчинена этой цели (раздел 1).
2. **М0 (триаж docs) — делаем**, вместе с чисткой тестов: приёмочные тесты
   прижившихся фич копились и не удалялись (раздел 5, М0-б).
3. **Движковый функционал — точно переводим на TS.** Сеттинговый
   (`modules/fallout`) — настолько живой и дорабатываемый, что его НЕ тянем:
   остаётся JS (раздел 2). Уже существующие TS-файлы сеттинга не откатываем.
4. Обновления ставятся патчами (`apply-patch.sh`) — серия остаётся цепочкой
   мелких самодостаточных патчей, каждый оставляет приложение рабочим.

## 1. Цель: ловить ошибки до старта

«До старта» — это лестница проверок, каждая стоит раньше следующей:

| Когда ловим | Инструмент | Что ловит |
|---|---|---|
| **При написании кода** (в песочнице, до сдачи патча) | `tsc --noEmit` strict по движку | несуществующие поля, неверные формы, null/undefined, неверные аргументы — весь класс «опечатка, которая выстрелит при запуске» |
| **При сдаче патча** (прогон в песочнице) | предохранители устава (паспорта, импорты, данные) | нарушение контрактов: новое поле стора без паспорта, битый импорт, дрейф данных |
| **При загрузке пакета** (в браузере, но до первого экрана) | runtime-гварды адаптера (М2) | битый/недостающий JSON сеттинга — ошибка с путём к файлу, а не падение в недрах экрана |
| **Никогда не должны ловить** | — | то, что сегодня ловится глазами владельца на живом приложении |

Смысл серии: **переместить максимум ошибок из последней строки в первую.**
Чем больше движка под строгим `tsc`, тем меньше классов ошибок вообще
способно доехать до владельца. Чего типизация не ловит — логику — держит
маленький набор предохранителей (раздел 5); огромная куча приёмочных тестов
для этого не нужна и удаляется.

Побочный эффект для сеттинга: сеттинг остаётся живым JS, но движок видит его
только через типизированную дверь (М2) — сломанный сеттинг роняет гвард на
входе с понятной ошибкой, а не экран при запуске.

## 2. Область серии: движок — TS, сеттинг — JS

| Слой | Судьба |
|---|---|
| `domain/` (математика движка) | **TS, серия М3** |
| `src/` (стор, сейвы, отладка) | **TS, серия М4** |
| `db/`, `i18n/`, движковые экраны `components/`, `App.tsx` | **TS, серии М5–М6** |
| `modules/fallout/**` (данные, экраны, выживание, крафт-окно, разбор, болезни) | **остаётся JS** — живой код, дорабатывается владельцем постоянно; уже существующие TS-файлы сеттинга (`survival.ts`, две TSX-модалки) не трогаем |
| новые фичи сеттинга (перки и пр.) | код в модуле на JS; всё, что фича просит у движка — через TS-контракты М2 |

Компенсация «живости» сеттинга — граница: типизированный адаптер +
runtime-гварды данных пакета (М2). Движок строг; сеттинг свободен; стык
охраняется. Это ровно модель `setting-contract.md`: «нет объявленного
файла — ошибка с путём», «чужой формат не подчищаем».

## 4. Принципы серии

1. **Один шаг = один патч.** Номер — следующий свободный (в цепочке 275–276,
   серия стартует от 277). После каждого патча: приложение рабочее,
   `npx vitest run` зелёный, `tsc --noEmit` чисто, e2e-проверка чистого
   checkout + `./apply-patch.sh N` (устав §2).
2. **Конверсия ≠ изменение поведения.** Патч-конверсия только переезжает на
   TS. Всё, что типизация вскрыла (возможный `null`, расхождение форм) —
   **отдельный** патч-фикс с тестом. Смешение запрещено.
3. **Храповик tsconfig:** `include` только растёт; предохранитель М1 не даст
   новому `.ts` остаться вне компилятора.
4. **Паспорт — в том же патче**, если тронут стор/сейв.
5. **`any` — исключение с комментарием**; внешние входы — `unknown` +
   гварды; legacy-формы — только внутри мигратора (engine-dna §7.3–7.4).
6. **Переименование почти безболезненно**: импорты в основном без расширений;
   НО в проекте 37 явных `.js`-импортов (~10 файлов) — при переименовании
   такого файла все явные ссылки правятся в том же патче (ловит
   предохранитель резолвинга). Дубль `.js`+`.ts` запрещён.
7. **Сеттинг не конвертируем и не трогаем лишний раз**: патчи серии не
   правят `modules/fallout/**` (кроме уже TS-файлов, если просят баги).
8. **Тесты — по политике раздела 5**, не «как получится».

## Критерий «файл переведён»

- расширение `.ts`/`.tsx`; строгие типы на экспортах; `any` — с комментарием;
- файл в `include` tsconfig (проверяет предохранитель М1);
- тесты, его касающиеся, зелёные; поведение не изменилось;
- приёмочные тесты области — удалены этим же патчем (см. раздел 5).

## 5. Политика тестов (новая, закрепляется в М0)

Владелец: «каждая фича писала свой тест, после приживания тест не удалялся и
они копятся; я бы вообще тесты из песочницы в репозиторий не тащил».
Политика это фиксирует, не теряя предохранителей:

**Два сорта тестов:**

1. **Предохранители** — остаются в репозитории НАВСЕГДА. Это тесты правил
   устава §3 и целостности данных (битые данные = падение при старте — ровно
   цель владельца). Полный список — ниже, ~18 файлов.
2. **Приёмочные** — инструмент разработки, не артефакт. Живут в песочнице,
   служат до сдачи патча; фича прижилась (e2e-проверка владельца) — тест
   умирает. **Новые приёмочные в патчи не входят вообще** — живут только в
   песочнице. Исключение: приёмочные движковых областей, которым скоро
   конверсия, — могут ехать в репо с пометкой `// ПРИЁМОЧНЫЙ (патч N): удалить
   при конверсии/приживании`, чтобы их можно было найти grep-ом.

**Почему не выкинуть совсем всё:** песочница пересоздаётся — нечто, чего нет
в репо, теряется между сессиями. Предохранители переживают сессии и держат
лестницу раздела 1. Всё остальное — действительно не должно копиться.

**Правило приживания (на будущее):** следующий патч, трогающий прижившуюся
фичу, удаляет её приёмочные тесты. Чистка идёт сама собой, копилки больше
нет.

**Конец серии:** в репозитории остаются только предохранители (~18 файлов);
приёмочные исчезают по мере конверсии областей (каждый патч М3/М4/М5 удаляет
базу своей области — типизация забирает её роль). Счёт тестов монотонно
падает: 86 → ~70 после М0-б → … → ~18 в конце серии.

   тихий `|| []` и не падение экрана при старте (setting-contract §11).
   Формы берутся из `docs/schema/01–06`.
3. **`Parameter`/модификаторы** — тип стека из `schema/06-modifiers.md`,
   задел под `modifiers-vision.md` и перки М7.

Контрактный тест: манифест ↔ типы ↔ файлы на диске.
