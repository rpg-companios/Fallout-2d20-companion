# План: каскад производных и TypeScript (серия движка Positronium)

**Статус:** третья редакция — разворот серии на каскад + универсальность
(решения владельца 2026-09-18, третья волна). Центр тяжести: не «перевод
файлов на TS ради TS», а **типизированный механизм выводимости** — движок
универсальный, Fallout — первый клиент, TS едет с ним.
**Связанные:** `docs/architecture/engine-charter.md`, `engine-dna.md`,
`setting-contract.md`, `docs/architecture/cascade-map.md` (карта каскада,
патч 279), `docs/schema/06-modifiers.md`, `docs/architecture/modifiers-vision.md`.

## 1. Почему так (кратко)

- Боль «одно обновилось — остальное стоит, пока руками не поправишь» —
  буквальное описание кода: 24 ручных вызова пересчёта, автоподписка без
  атрибутов, три копии правды (стор, движок, экраны). Детали и таблицы —
  `cascade-map.md`.
- Смена языка программирования ничего из этого не решает: боль
  архитектурная, не языковая; реактивный каскад в JS/TS строится полноценно.
  Переписывать 38 тыс. строк работающей программы ради языка — месяцы без
  фич и те же вопросы в новом языке.
- TS решает другой, тоже реальный класс — ошибки форм («поля нет», «в одном
  месте число, в другом объект») — самый частый в истории проекта. Поэтому
  TS остаётся в серии, но как рельсы, а не поезд.

## 2. Целевая картина

```text
СЕТТИНГ (пакет) объявляет:           ДВИЖОК исполняет:
  параметры (база + модификаторы)  →  хранение, стек модификаторов
  производные ({id, deps, формула}) →  вывод при чтении + кеш
  каунтеры (мана, крышки, ОЗ)      →  транзакции, отказ при нехватке
  потолки рангов (от атрибута)     →  ленты
  гейты (навык≥4 для заклинания)   →  проверка требований
  реакции (макс ОЗ упал → кламп)   →  реестр реакций
  экраны-кирпичи                   →  навигация/рендер (setting-contract)
```

Движок не знает ни SPECIAL, ни радиации, ни маны. Fallout регистрирует свои
формулы (сегодня они захардкожены в движке — `cascade-map.md` §2), тестовый
сеттинг — свои. Механизм регистрации — развитие уже существующего реестра
расширений состояния (так уже живёт выживание) и кирпичей setting-contract.

Формат сейвов не меняется: производные и так не пишутся на диск.

## 4. Тестовый сеттинг (спека владельца)

5 атрибутов; 5 производных (здоровье, манна, сила магии, защита, нападение);
7 навыков; 5 заклинаний. Атрибуты влияют на производные. Заклинания тратят
манну; манна = атрибут + навык. Бонусы +5/10/15% к силе магии / защите от
магии. Гейт: некоторые заклинания нельзя взять без навыка ранга 4. Число
рангов навыка зависит от показателя атрибута.

Что спека нарочно проверяет на прочность: процентные модификаторы (в
нынешнем стеке только +/−), каунтер с производным максимумом, потолок
рангов от параметра, гейты-требования, производные от двух источников
(атрибут + навык). Критерий успеха — §2 `cascade-map.md`.

## 5. Принципы серии (без изменений с прошлой редакции)

1. Один шаг = один патч; после каждого — рабочее приложение, зелёные
   предохранители, `tsc --noEmit` чисто, e2e на чистом main.
2. Конверсия/рефакторинг ≠ изменение поведения; вскрытое — отдельным
   патчем-фиксом.
3. Храповик tsconfig; паспорт — в том же патче; `any` — исключение с
   комментарием; legacy — только в миграторе.
4. Сеттинг — JS, движок — TS; движок не импортирует сеттинг (нарушение в
   resolvers чинится в МК-3; новых не добавляем).
5. Тесты — по политике устава §2а: предохранители навсегда, приёмочные —
   песочница, не копятся.

## 6. Риски и страховка

| Риск | Страховка |
|---|---|
| Каскад меняет поведение незаметно | карта §2–5 фиксирует текущие значения; equivalence-тесты на формулы при переезде |
| Контракт спроектирован под Fallout | тестовый сеттинг по спеке владельца — обязательный второй клиент (МК-2 до реализации) |
| «Только числа» зашито в фундамент | виды значений версионируются в контракте (§3 МК-1) |
| Поломка сейвов | производные не пишутся на диск; формат не трогаем; паспорта + dirty-save-v18 |
| Смена реактивного ядра окажется нужной | решение по фактам после МК-1/МК-2; критерий — число настоящих реакций (карта §6: сегодня единицы) |
| Забытая производная при переезде | карта — чек-лист; каждый шаг МК-3 закрывает свои строчки карты |
| Живой сеттинг ломает движок | гварды данных пакета при загрузке (МК-1), ошибка с путём |

## 7. Сводка одной страницей

```text
Боль: производные хранятся и пересчитываются 24 ручными вызовами; Fallout-
формулы застряли в движке; экраны держат третьи копии. Формат сейвов при
этом чист — чинить можно без миграций.

Решение: движковый механизм выводимости. Сеттинг объявляет параметры,
производные, каунтеры, ленты, гейты, реакции — движок исполняет и
каскадирует. Fallout — первый клиент, мини-сеттинг владельца — второй.
TS — язык контракта и движка; сеттинг — живой JS.

279 карта каскада (готова) → 280 предохранители TS → 281 контракт →
282 семантика процентов → 283 фазы модификаторов (порядок объявляют
правила) → 284 тестовый сеттинг → 285+ реализация и переезд
Fallout-формул в модуль → М3–М8 конверсия и экраны.

Реактивное ядро не меняем, пока факты (карта реакций) не скажут обратное.
```
