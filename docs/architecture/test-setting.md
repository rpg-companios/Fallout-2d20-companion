# Тестовый сеттинг (МК-2, патч 285)

> Второй клиент контракта выводимости. Спека владельца — дословно в
> `docs/architecture/cascade-map.md` §8. Критерий: сеттинг описывается
> **регистрацией без правок движка** — патч 285 не трогает `src/` вообще,
> это видно в диффе.

## Состав (спека → реализация)

| Спека владельца | Где живёт |
|---|---|
| 5 атрибутов | `modules/test-setting/index.js`: `ATTRIBUTES` (сила, ловкость, интеллект, дух, удача) |
| 7 навыков | `SKILLS`, каждый с атрибутом-покровителем |
| 5 производных (здоровье, манна, сила магии, защита, нападение) | `TEST_SETTING.derived`, `kind: 'max'/'derived'` |
| манна = атрибут + навык | `maxMana = Интеллект + Колдовство` — формула сеттинга, дословно по спеке |
| +5/10/15% к силе магии / защите от магии | модификаторы `'%'` на `test.derived.magicPower` / `test.derived.defense` (применяются к базе формулы, режим округления — по объявлению значения) |
| заклинания тратят манну | `spells.js`: 5 заклинаний со стоимостью (`manaCost`) |
| гейт «навык ранга 4» | `SPELL_REQUIREMENT` + `checkRequirements` |
| число рангов навыка зависит от атрибута | `kind: 'rankCeiling'` для каждого навыка, ступени `RANK_BANDS` от атрибута-покровителя |

Числовые правила (здоровье = 10 + Сила×2, ступени 1/4/7/10 → потолки 1/2/3/4) —
выбор мини-сеттинга: контракту всё равно, какие формулы объявляет сеттинг.

## Дверь JS→TS

Сеттинг — живой JavaScript (по плану серии TS-конверсия не трогает сеттинги).
Форма декларации проверяется при регистрации: `registerTestSetting(registry)`
сначала зовёт `validateSettingExtension`, потом регистрирует. Кривая декларация
падает на регистрации, а не посреди игры.

## Изоляция

Модуль **не импортируется работающей программой** — ни один экран, действие
или оркестратор. Его импортирует только приёмочный тест
`__tests__/settings/test-setting.test.js` (помечен «удалить при приживании»,
МК-3). Тест также проверяет, что модуль не импортирует ничего из движка,
кроме контракта и реестра, — самодостаточность декларации.

## Песочница (патч 286, слово владельца: только разработка)

Экран-кирпич `modules/test-setting/screens/SandboxScreen.js`: атрибуты
(степперы 0–12), навыки (0 — потолок ранга от атрибута-покровителя, кнопка
«+» гаснет у потолка), бонусы-переключатели (+5%/+10% к силе магии, +15% к
защите), производные и потолки счётчиков — всё пересчитывается каскадом
реестра без единого ручного вызова; заклинания показывают гейт («нужен
ранг 4») и карман («мало манны»).

**Показ — только среда разработки:** вкладка «Песочница» монтируется в
App.js за гейтом `__DEV__` (слово владельца: «в основной программе не
показывать вообще»). Продакшн-сборка её не видит. Логика экрана — в чистой
вью-модели `viewModel.js` (покрыта тестом без react-native), реестр
песочницы — ленивый синглтон `sandbox.js`. Хранилище персонажа не трогается.
