## 2. Система правок (цикл сдачи патча)

1. Один шаг = один патч с номером N. После шага приложение рабочее.
2. Перед сдачей ОБЯЗАТЕЛЬНО: полный `npx vitest run` + `tsc --noEmit` (все предохранители зелёные).
3. Коммит `N (метка): суть` в ветку `arena/01a08a17-fallout-2d20-companion` →
   `git format-patch <prev>..HEAD --stdout > patchs/N-name.patch` → коммит файла патча → push.
4. Владелец применяет `./apply-patch.sh N` (скрипт сам ставит недостающую цепочку).
   **Ручной перенос файлов запрещён** (инцидент 225).
5. e2e-проверка разработчика (каждый патч): чистый checkout 565b417 из локального клона,
   `sed` ветки в apply-patch.sh на актуальную, `./apply-patch.sh N`, сверка ключевых файлов
   `git hash-object` с рабочим деревом (IDENTICAL).
6. Отчёт владельцу: что случилось игровыми терминами + примеры; отдельно — риски и найденные дефекты.
7. **Правило вопросов:** есть варианты развития или неясность — спрашивать обязательно, не додумывать.

### Окружение разработчика (песочница)
- Песочница периодически пересоздаётся: `node_modules` исчезает → `npm ci`;
  `.git` откатывается к 565b417 при живом рабочем дереве → восстановление:
  `git fetch origin <ветка> && git reset FETCH_HEAD` (дерево не трогать; коммит+пуш после КАЖДОГО шага).
- Названия инструментов по памяти не писать; heredoc — только полная перезапись файла;
  `require()` в ESM-коде запрещён (vitest); `sed`-правки «по памяти» — нет.

## 4. Инварианты геймплея (решения владельца, по книге)

- **Усталость:** −⌊N/2⌋ текущих ОЗ за игровой час активности (232). Сон из правила исключён;
  лечение — постелью. Сжигание еды/воды сном НЕ менять.
- **Болезни:** «Сопротивляться» — одна попытка в сутки (215); лечение снижает ранги (240).
- **Предмет = база + id модов на предмете** (237). Имена собирает каталог («тупой сборщик»);
  пример: `weapon_huntingRifle_05_76_48_35` → «.50 длинноствольная охотничья высокоемкая тихая винтовка».
- **Формат-v2 (247):** картотека модов в запись не идёт; мост в `deserializeState` переносит
  записи старых сейвов на предметы (до канонизации id); записи без пары — read-only в инвентаре.
- **Смена комплекта (241):** переживают ОЗ/радиация/сцены/условия/журнал доз/tagged-навыки
  (`resetKitAndRewards({keepSkills})`). `resetCharacterStore` — «жёсткий» сброс: любое его новое
  использование обязано собирать survivor-state осознанно (инцидент 241).
- **НЕ ТРОГАТЬ без владельца:** `migrations.js`, `kit.caps`, `data.caps`, `EquipmentKitModal.js`,
  `kitResolver.js`, i18n `screen.caps.*` / `capsModal.*`.
- **Силовая броня (227):** алерты PA-слайса — временный компромисс; программный equip СБ до
  готовности состояния запрещён (revalidation не отменяет надетое).
- **UI:** без текстовых подсказок «что делать» — индикация цветом (231).

- `src/store/characterStore.js` — единственный источник; слайсы: `robotSlice`, `powerArmorSlice`,

- Сейвы: `src/saves/characterSaves.js` (buildSnapshot/save/load/list/delete/автосейв);
  db — `db/` (SQLite/WebAdapter — канон), облако — `components/cloudSync/`, файлы — `domain/characterTransfer`.
  Автосейв: только `isSaved+currentCharacterId`, debounce 500 мс, пропуск неизменённого JSON;
  стартует в App.js после dbReady+characterStoreReady. PA-таймер — useEffect в App.js.
- Универсальный движок: общее ядро + сеттинг-паки через реестр `stateExtensions`
  `{id, fieldKey, factory, hydrate, reset}` (207) и `registerStateMigration` (встраивание в цепочку).
  Сейв = конверт с версиями (`schemaVersion`).

## 7. Уроки (не повторять)

- Воссоздавая хелперы — брать оригинал из git (`git show`), не писать «по докстрингу» (242, preferFilled).
- Наивные `not.toContain` ломаются об комментарии-историю — регексы с контекстом или AST.
- AST-тесты не резолвят импорты Metro — см. предохранитель 6 (249).
- Большой патч без промежуточных коммитов = риск. Коммит+пуш после каждого шага.
- Экраны переводить на TS, когда они успокоились; кипящий код — после фичевой волны (решение по Inventory).
