# Данные крафта: где лежат рецепты и что в них

**Статус:** патч 249. Движок крафта — следующий шаг; этот документ описывает только данные.
**Связанные документы:** `docs/architecture/engine-dna.md`, `docs/architecture/engine-charter.md`,
`docs/reference-data/CRAFTING-MAPPING.md`, `setting-contract.md`.

---

## 1. Кто что знает

- **Данные (пакет сеттинга)** — что в этом мире можно сделать, из чего и кому это доступно.
  Лежат в `modules/fallout/data/crafting/`.
- **Движок (следующий патч)** — как проверять доступность, как списывать, как выдавать,
  как бросать на результат. Названий предметов, имён перков и страниц книги движок не знает.
- **Генератор `scripts/build-crafting-data.mjs`** — переводчик «человеческое имя → id»:
  читает справочный датасет (чужие имена и строки) и пишет файлы категории `crafting`.
  Только он имеет право «узнавать» предметы по имени; программа — никогда.

```text
docs/reference-data/pipboyapp_crafting.json  (справочные данные, чужие имена и строки)
        │  генератор: имя → id нашего каталога; перк → id перка; навык → ключ
        ▼
modules/fallout/data/crafting/*.json          (только id)
        ▼
реестр данных сеттинга (куда смотреть) → движок крафта (что с этим делать)

docs/reference-data/Missing_craft.json        (обменник: где каталог молчит)
```

## 2. Формат

Индекс категории — `crafting/index.json`:

```json
{ "id": "crafting", "benches": ["chemistry", "cooking", "weapons"],
  "recipes": [ { "file": "ammo.json", "bucket": "ammo", "count": 19 } ] }
```

Файлы разложены **по тому, что крафт даёт** (боеприпасы, оружие-взрывчатка, препараты,
еда, напитки, разное) — так список рецептов на экране не придётся пересобирать из шести
станков. Кому какой станок нужен — поле `bench` внутри каждого рецепта: оно нужно движку
для гейта «рядом должна быть кухня/верстак», а не для раскладки файлов.

Рецепт:

```json
{
  "id": "ammo_38",
  "bench": "weapons",
  "requires": {
    "skill": "REPAIR",
    "complexity": 1,
    "perks": [ { "perkId": "ammosmith", "rank": 1 } ]
  },
  "materials": [ { "itemId": "item_common_materials", "count": 2 } ],
  "derivedMaterials": true,
  "output": { "itemId": "ammo_38", "itemType": "ammo", "quantity": { "base": 10, "cd": 5 } },
  "sourcePage": 211
}
```

| Поле | Чейство | Смысл |
|---|---|---|
| `id` | данные | ключ рецепта = **id предмета, который он даёт** (`chem_mentats_berry`). Уточнение через `_` допускается только если предмет умеют давать несколько рецептов (боеприпасы: ранг перка меняет рецепт); уникален во всех файлах категории |
| `bench` | движок | тип верстака (`weapons`, `armor`, `powerArmor`, `robot`, `chemistry`, `cooking`) |
| `requires.skill` | движок | ключ навыка из `ALL_SKILL_KEYS` — по нему движок берёт ранг героя |
| `requires.complexity` | книга | сложность рецепта; движок вычитает из неё ранг навыка, не ниже 0 |
| `requires.perks[]` | данные | особенность, разрешающая рецепт, и минимальный ранг |
| `materials[]` | книга | что списать: `itemId` + количество |
| `derivedMaterials` | справочное | материалы взяты не из таблицы рецепта, а по печатному правилу «материалы определяет сложность» (с. 210); список совпадает с кривой сложности |
| `output.itemId` / `itemType` | данные | что выдать; тип обязан совпасть с тем, как предмет описан в каталоге |
| `output.quantity` | данные/книга | `1` или `{ base, cd }` — боевые кубики к количеству (боеприпасы: объём находки, `docs/reference-data/ammo-found-table.json`) |
| `sourcePage` | справочное | страница книги, для ревизии данных; на поведение не влияет |

Чего в рецептах нет намеренно: имён предметов и перков, человекочитаемых описаний,
названий навыков, строк «Common Materials». Имена собирает каталог (engine-dna §4.3),
а значит ссылка обязана быть id.

## 3. Чего здесь ещё нет (и не должно появиться молча)

- **Модификации.** Ветка отложена по решению владельца: крафт выдаёт предметы.
  У модов оружия и брони колонки сложности/перков/материалов уже проставлены в данных
  (`equipment/weapon_mods.json`, `equipment/armor/armor_mods.json`), так что для их
  ветки достаточно будет переложить их в тот же формат — отдельным патчем.
- **Дыры каталога.** Девять препаратов упираются в ингредиенты, которых у нас нет как
  предметов (части существ, довоенная бытовая химия); девять рецептов дротиков шприцера
  и «верстак-кухня» — в то, что самих этих предметов в каталоге нет. Такие рецепты
  генератор не выпускает (придумывать предмет, его вес или цену он права не имеет) и не
  выбрасывает молча: они выгружаются в `docs/reference-data/Missing_craft.json` —
  файл-обменник с той же структурой полей, что у рецептов, где неизвестное записано
  строкой `unknown`. Владелец дописывает недостающее по своим книгам и возвращает файл;
  закрытые позиции переезжают в данные через правила генератора (соответствие имён или
  явные ингредиенты), а не правкой JSON руками. Совпадение названий («Tato Juice» →
  «Potato Juice», «Mutant Hound Chops» → «Mutant Hound Ribs») — соответствия с причиной,
  они видны в отчёте `CRAFTING-MAPPING.md`.
- **Верстак как предмет.** «Верстак» в данных — поле `bench`, а не вещь в сумке.
  Нужен ли станок отдельным предметом в каталоге — решение владельца.

## 4. Числа, которые движок будет читать из настроек, а не из данных

По печатным правилам (с. 210–211): длительность часа работы и 20 минут на кухне,
сокращение вдвое за 2 ОД при успехе, +30/+10 минут за осложнение, сгорание ингредиентов
при провале на кухне и в химии. Эти значения — **настройки** (как шкала выживания), а не
поля рецепта: один и тот же рецепт не может иметь разную длительность, а правила за
столом у разных столов разные. В данных рецептов их нет намеренно.

## 5. Как править

1. Поправить источник (справочные данные) или таблицы генератора. Вернуть из
   доводки `Missing_craft.json` — тоже источник правды на этот шаг: соответствия
   и числа переносятся в таблицы генератора, файл перегенерируется сам.
2. `node scripts/build-crafting-data.mjs` — перегенерировать файлы, отчёт и обменник.
3. `npx vitest run __tests__/crafting` — предохранитель: индекс, ссылки, отсутствие имён,
   кривая материалов, совпадение файлов с генератором и обменником.
4. `npx vitest run` и `tsc --noEmit` целиком.

Править `modules/fallout/data/crafting/*.json` руками нельзя: тест сверяет их с выводом
генератора и упадёт.
