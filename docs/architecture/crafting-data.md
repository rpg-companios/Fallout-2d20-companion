# Данные крафта: где лежат рецепты и что в них

**Статус:** патчи 249–250; данными срез закрыт (в обменнике одна позиция). Движок крафта — патч 251, контракт механики: `docs/architecture/crafting-engine.md`; здесь только данные.
**Связанные документы:** `docs/architecture/engine-dna.md`, `docs/architecture/engine-charter.md`,
`docs/reference-data/CRAFTING-MAPPING.md`, `setting-contract.md`.

---

## 1. Кто что знает

- **Данные (пакет сеттинга)** — что в этом мире можно сделать, из чего и кому это доступно.
  Лежат в `modules/fallout/data/recipes/` (реформа 269: движок не знает ни рецептов,
  ни верстаков — реестр указывает ему файлы, и только).
- **Движок (следующий патч)** — как проверять доступность, как списывать, как выдавать,
  как бросать на результат. Названий предметов, имён перков и страниц книги движок не знает.
- **Генератор `scripts/build-crafting-data.mjs`** — переводчик «человеческое имя → id»:
  читает справочный датасет (чужие имена и строки) и пишет файлы категории `crafting`.
  Только он имеет право «узнавать» предметы по имени; программа — никогда.

```text
docs/reference-data/pipboyapp_crafting.json  (справочные данные, чужие имена и строки)
        │  генератор: имя → id нашего каталога; перк → id перка; навык → ключ
        │  таблицы правил: кривая «сложность → материалы», соответствия имён,
        │  исправления владельца BOOK_CORRECTIONS (числа приоритетнее источника)
        ▼
modules/fallout/data/recipes/*.json           (только id)
        ▼
реестр данных сеттинга (куда смотреть) → движок крафта (что с этим делать)

docs/reference-data/Missing_craft.json        (обменник: где каталог молчит)
```

Ссылки рецептов разрешаются не только по снаряжению и расходникам: с патча 250
в списке справочников каталога — хлам (`modules/fallout/data/junk.json`),
материалы (`modules/fallout/data/materials.json`) и каталог боеприпасов, куда
дописаны девять дротиков шприцера. Имена предметов для сверки берутся из
i18n-зеркал этих же каталогов (`i18n/en-EN/data/junk.json` и др.).

## 2. Формат

Индекс категории — `recipes/index.json`:

```json
{ "id": "crafting",
  "recipes": [ { "file": "ammo.json", "category": "ammo", "count": 28 } ] }
```

Файлы разложены **по тому, что крафт даёт** (боеприпасы, оружие, препараты, еда,
напитки) — файл-раздел и есть категория. Верстаков в данных нет (реформа 269, решение
владельца): печать смешивала верстаки внутри одного файла, поэтому «кто где делает»
перестало быть свойством рецепта, а право провала сжигать материалы — стало (см.
`failBurnsMaterials`). Порядок `recipes[]` манифеста — он же порядок вкладок окна.

Рецепт:

```json
{
  "id": "ammo_38",
  "requires": {
    "skill": "REPAIR",
    "complexity": 1,
    "perks": [ { "perkId": "ammosmith", "rank": 1 } ]
  },
  "materials": [ { "itemId": "item_common_materials", "count": 2 } ],
  "outputQuantity": { "base": 10, "cd": 5 }
}
```

| Поле | Чейство | Смысл |
|---|---|---|
| `id` | данные | ключ рецепта = **id предмета, который он даёт** (`chem_mentats_berry`); отдельного `output.itemId` нет (269: «зачем усложнения — какой предмет на выходе»). Уточнение через `_` допускается только если предмет умеют давать несколько рецептов (боеприпасы: ранг перка меняет рецепт); уникален во всех файлах категории |
| `requires.skill` | движок | ключ навыка из `ALL_SKILL_KEYS` — по нему движок берёт ранг героя |
| `requires.complexity` | книга | сложность рецепта; движок вычитает из неё ранг навыка, не ниже 0 |
| `requires.perks[]` | данные | особенность, разрешающая рецепт, и минимальный ранг |
| `materials[]` | книга | что списать: `itemId` + количество |
| `outputQuantity` | данные/книга | `1` или `{ base, cd }` — боевые кубики к количеству (боеприпасы: объём находки, `docs/reference-data/ammo-found-table.json`) |
(Сгорание при провале — не поле записи: в печатном наборе оно совпадает с проверочным
навыком, и правило живёт строкой в `CRAFT_RULES.failBurnsMaterialsSkills` — реестре
настроек модуля; генератор сверяет разрез с верстаком источника и падает при расхождении.)

Чего в данных больше нет (реформы 269–270): `bench` и `sourcePage` — страницы и верстаки
сидят в отчёте генератора (`CRAFTING-MAPPING.md`) и в `Missing_craft.json`, где они
справочные; `derivedMaterials` — служебные пометки в данных не живут, их смысл
проверяется напрямую: набор только из сырья обязан равняться кривой сложности;
`failBurnsMaterials` — 74 повтора свернуты в правило навыка (270, «лишние поля ни к
чему, когда есть реестр»). Пути файлов группы тоже не размножаются по документом:
`data/recipes/index.js` и `data/junk/index.js` — листы групп, их читают реестр и
каталог; движок и окно смотрят в реестр.

Чего в рецептах нет намеренно: имён предметов и перков, человекочитаемых описаний,
названий навыков, строк «Common Materials», подписей категорий и редкостей. Имена
собирает каталог (engine-dna §4.3), а значит ссылка обязана быть id.

## 3. Чего здесь ещё нет (и не должно появиться молча)

- **Модификации.** Ветка отложена по решению владельца: крафт выдаёт предметы.
  У модов оружия и брони колонки сложности/перков/материалов уже проставлены в данных
  (`equipment/weapon_mods.json`, `equipment/armor/armor_mods.json`), так что для их
  ветки достаточно будет переложить их в тот же формат — отдельным патчем.
- **Дыры каталога (закрыты в патче 250).** Девять препаратов упрались в ингредиенты,
  которых не было как предметов (части существ, довоенная бытовая химия), девять
  рецептов дротиков шприцера и «верстак-кухня» — в отсутствие самих этих предметов.
  Владелец дописал справочники (таблица дикоросов и три новые еды, каталоги хлама и
  материалов, дротики в боеприпасах) — 19 позиций переехали в данные через правила
  генератора, не правкой JSON. Механизм обмена живёт в
  `docs/reference-data/Missing_craft.json`: та же структура полей, что у рецептов,
  неизвестное записано строкой `unknown`; сейчас в обменнике одна позиция —
  «Cooking Station» (предмет не описан). Исправления печатных чисел, которые диктует
  владелец, — в `BOOK_CORRECTIONS` генератора: подмена видна в отчёте, осиротевшая
  правка роняет генератор. Совпадения названий («Tato Juice» → «Potato Juice»,
  «Mutant Hound Chops» → «Mutant Hound Ribs», «Berserk Syringe» → дротик «Berserk»)
  — соответствия с причиной, они видны в отчёте `CRAFTING-MAPPING.md`.
- **Разборка хлама.** Антисептик, асбест и прочий хлам — предметы с весом и ценой;
  правило «достаётся разбором» (в книге — у перка «Мусорщик») — отдельная ветка,
  в данных рецептов её нет. Таблицы компонентов (Household Items 1, Animal Products
  and Food) создавались как пополняемые владельцем.
- **Верстак как предмет.** С полем `bench` данные расстались (269): он не гейт
  (станков в сумке нет), а смешанные по верстакам файлы делали его ложным свойством
  рецепта. Нужен ли станок отдельным предметом в каталоге — решение владельца.

## 4. Числа, которые движок будет читать из настроек, а не из данных

По печатным правилам (с. 210–211): длительность часа работы и 20 минут на кухне,
сокращение вдвое за 2 ОД при успехе, +30/+10 минут за осложнение, сгорание ингредиентов
при провале на кухне и в химии. Эти значения — **настройки** (как шкала выживания), а не
поля рецепта: один и тот же рецепт не может иметь разную длительность, а правила за
столом у разных столов разные. В данных рецептов их нет намеренно.

## 5. Как править

1. Поправить источник (справочные данные) или таблицы генератора. Вернуть из
   доводки `Missing_craft.json` — тоже источник правды на этот шаг: соответствия
   и числа переносятся в таблицы генератора, файл перегенерируется сам.
2. `node scripts/build-crafting-data.mjs` — перегенерировать файлы, отчёт и обменник.
3. `npx vitest run __tests__/crafting` — предохранитель: индекс, ссылки, отсутствие имён,
   кривая материалов, совпадение файлов с генератором и обменником.
4. `npx vitest run` и `tsc --noEmit` целиком.

Править `modules/fallout/data/recipes/*.json` руками нельзя: тест сверяет их с выводом
генератора и упадёт.
