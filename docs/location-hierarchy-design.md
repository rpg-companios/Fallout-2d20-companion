# Иерархия пространств и доступ (тезис 13)

Ревизия: 2026-11-04, патч **523** — первый шаг этапа. Документ фиксирует слово
владельца, принятые технические допущения и границу сделанного.

## 1. Слово владельца (окончательные решения)

- **Граф, а не дерево.** Локация может содержать локации, в которых тоже
  локации; пол, этаж, шкаф могут быть локациями. Контейнер может содержать
  контейнеры. Разрешены **несколько родителей** и **циклы** A–B–C–A,
  ветвящиеся лабиринты.
- **Наследование кодов:** «все те же коды от каждого родителя» — объединение
  `roomCodes` узла и всех его родителей. `roomCodes` задают **видимость групп**,
  а состояние и ресурсы локации **общи** для всех привязанных комнат: взлом в
  партии 1 виден партии 2, покупка в партии 2 опустошает торговца партии 1,
  крышки торговца общи, партия 3 не видит ничего, пока её код не добавят.
  Серверные комнаты только объединяют игроков и разделяют группы.
- **Вложенность задаётся** вручную или переносом карточки внутрь; перенесённый
  ребёнок автоматически привязывается к комнате (комнатам) родителя.
- **«Верхнего родителя» нет.** Любой узел, у которого есть хотя бы один ребёнок,
  может «заблокировать всё». Блокируются только запираемые вещи; на заводе всё
  может быть изначально открыто.
- **Замок — граница видимости.** Не вошёл в локацию — не знаешь, что за ней;
  запертый сундук скрывает содержимое. Взлом **локации даёт вход**, взлом
  **контейнера — содержимое**.
- **Взлом адресный, без каскада.** Открывается ровно та точка, к которой
  применён взлом; транзитивной цепочки A → B → C нет.
- **Ключ не знает область, точка знает свой ключ.** Ключ может быть назначен
  многим точкам («поточечно»), но не открывает каскад. Ключ не исчезает и
  открывает дверь повторно, если Мастер запер её снова. Взлом без одобрения
  Мастера не повторяется.
- **Одна сессия** живёт, пока игрок не вышел из родительской локации или не
  нажал «Покинуть локацию»; Мастер закрывает сцену сам.
- **Вторая строка «проверка»** ссылается на уже созданные точки в той же
  комнате (до двух, через «ИЛИ»), а не создаёт новую точку из формы. Мастер
  может открыть доступ вручную, сняв блокировку узла локации.

## 2. Технические допущения (предложены ассистентом, приняты в 523)

Владелец не возражал после явного перечисления; любое можно поправить
следующим обновлением, не переделывая граф.

1. Одна доска мини-игры на локацию, один оператор; остальные наблюдают.
2. Канон — локальная БД Мастера + Google Drive; сервер держит снимок в памяти;
   без Мастера в сети игроки видят только чтение. Офлайн-очередей,
   конфликтов и `baseRevision` нет.
3. Узлы без замка остаются открытыми.
4. Повторный выбор того же источника взлома запрещён; ключи и «ИЛИ»-ворота
   не являются источниками каскада.

## 3. Что сделано в 523

- **`server/locationGraph.js`** (канон CommonJS) и **`domain/locationGraph.js`**
  (клиентская точка входа). Канон лежит в `server/`, потому что лёгкий деплой
  NetAngels копирует в `app/` только `server/` + `ws`. Чистые функции:
  `buildLocationGraph`, `descendantsOf`, `ancestorsOf`, `effectiveRoomCodes`,
  `hasChildren`, `lockAllTargets`, `hiddenBehindLock`, `flattenForSession`,
  `buildGraphFromSession`, `addressableUnlock`. Обходы защищены от циклов.
- **Вложенность у любого узла.** `normalizeContainerEntity` больше не
  ограничивает `links` только локациями. Новый `buildLocationSessionNodes`
  собирает сессию по всему графу: локация в локации, контейнер в контейнере,
  несколько родителей через `parentIds`, `childIds`, `depth`, эффективные
  `roomCodes`. Прежний `buildHubSessionNodes` сохранён для совместимости.
- **Сервер сессий.** Узлы и сама сессия хранят `parentIds`/`childIds`/`depth`/
  `roomCodes`; `linkedCheckIds` на уровне сессии больше не теряется; вложенная
  локация сохраняет `kind: 'hub'`. `sanitizeSessionForMember` скрывает всех
  потомков запертого узла — замок стал границей видимости.
- **«Заблокировать всё» и адресное открытие.** `applySessionLockAll`,
  `applySessionUnlock`, команды `lockAll` / `unlock` в `session.updateRates`
  (только владелец комнаты), кнопка в живой панели Мастера, парные строки
  RU/EN. Блокируются только запираемые потомки.
- **Без каскада.** Точка, открытая чужим событием через явную ссылку, больше не
  становится новым источником: событие порождает только ключ или собственная
  мини-игра. Явные ссылки «ИЛИ» на уже созданные точки работают.
- **Общие состояние и ресурсы.** Реестр рассылает ОДИН объект сессии всем
  привязанным комнатам (`boundRooms`), и каждая мутация (правки, взятие добычи,
  сделка, закрытие) обновляет его во всех комнатах. Комната, чей код не в
  `roomCodes`, не видит сессию вообще.
- **Одна сессия.** Игрок ходит по стеку вложенных локаций («← Назад»); сессия
  не гаснет при возврате к родителю. «Покинуть локацию» сбрасывает стек и
  отключает только этого игрока, сцена остаётся открытой для остальных.

## 4. Что осталось за границей 523

- Адресный взлом **локации как вход** и **контейнера как содержимое**: сейчас
  взлом снимает `locked` с точки, но явная семантика «вход / содержимое» в UI
  ещё не разведена.
- Общая доска мини-игры для всех привязанных комнат: `terminalStates` и
  `accessEvents` пока живут на комнате, а не на локации.
- «Заблокировать всё» пока действует на живую сессию; persisted-состояние
  карточек Мастера при перевыдаче берётся из БД Мастера.
- Ручное связывание «второй строки проверки» с уже созданными точками в форме
  и запрет повторного выбора источника.
- Настройка «заблокировать всё» на конкретном узле из карточки (сейчас кнопка
  в живой панели работает от корня сессии; сервер принимает любой узел с
  детьми).
