# Установка патча 521: мелочи «Общего хранилища»

Патч подготовлен от состояния **версии 520** (коммит `e68831c`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–521
цепочкой.

> Владелец: «Прошлые уточнения запустить после работы над складом». Последний
> тезис живого плана — «Мелочи склада: лимиты и стаканье, поведение при
> удалении записи-шаблона, тихое срабатывание ключа без уведомления Мастеру».

## Что добавлено

### 1. Стаканье одинаковых предметов

Новый чистый модуль `server/partyStorageRules.js`. Ключ стаканья строится по
снимку предмета без служебных полей экземпляра (`uniqueId`,
`equipInstanceId`, `stackKey`, `equipped`, `locked`, `appliedMods`,
`quantity`) и не зависит от порядка полей. Два одинаковых предмета, положенные
в разное время и разными игроками, теперь лежат одной строкой; ключевые записи
не стакаются. Когда стек заполнен (999), излишек уходит в новую строку, а не
пропадает. Правило работает и в старом сообщении `storage.deposit`, и в
атомарном `storage.transfer`.

### 2. Лимиты склада

| Ограничение | Значение |
| --- | --- |
| Строк на складе, включая ключи | 200 |
| Предметов в одном стеке | 999 |
| Операций в одном переносе | 50 |
| Предметов за одну операцию | 999 |

Превышение возвращает новый код `STORAGE_FULL` (зеркало в
`src/room/roomProtocol.ts`) **до** единого изменения `room.partyStorage`, так
что перенос остаётся атомарным и при переполнении. Импорт снимка из файла сверх
лимита отклоняется целиком. В окне склада вместо технического кода игрок видит
парную строку на русском и английском.

### 3. Два правила, которые уже работали

- Удаление записи-шаблона не гасит уже добытую запись (514): привязка хранится
  в родителе.
- Найденный ключ открывает точку без мини-игры и без уведомления Мастеру (516):
  `keyWonGame` в `server/roomRegistry.js` явно не шлёт уведомление.

Оба закрыты приёмочным тестом `__tests__/room/storage-polish-521.test.js`,
чтобы не потеряться при будущих правках.
