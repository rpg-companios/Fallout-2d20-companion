# Установка патча 523: граф пространств

Патч подготовлен от состояния **версии 522** (коммит `6fcd14e`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–523
цепочкой.

> Владелец: «Локация может содержать локации, в которых тоже локации...
> контейнеры в контейнерах, несколько родителей, циклы A–B–C–A... Замок как
> граница видимости... взлом адресный, без каскада... «заблокировать всё» на
> любом узле с детьми... коды комнат задают видимость групп, а состояние
> локации общее для всех привязанных комнат». Полный контракт —
> `docs/location-hierarchy-design.md`.

## Что добавлено

### 1. Граф вместо дерева

`server/locationGraph.js` (канон CommonJS) + `domain/locationGraph.js` (точка
входа для клиента). Канон в `server/` — лёгкий деплой NetAngels копирует в
`app/` только `server/` + `ws`, дубля правил нет.

- рёбра `links` разрешены у **любого** узла (`normalizeContainerEntity`);
- `buildLocationGraph`, `descendantsOf`, `ancestorsOf`, `effectiveRoomCodes`,
  `hasChildren`, `lockAllTargets`, `hiddenBehindLock`, `flattenForSession`,
  `buildGraphFromSession`, `addressableUnlock`;
- циклы и несколько родителей допустимы, все обходы защищены множеством
  посещённых узлов;
- коды комнат узла = объединение собственных кодов и кодов всех родителей;
- новый `buildLocationSessionNodes` собирает сессию по всему графу, прежний
  `buildHubSessionNodes` сохранён для совместимости.

### 2. Замок как граница видимости

`sanitizeSessionForMember` скрывает игроку **всех потомков** запертого узла,
а не только его содержимое. Сама «дверь» видна. Мастер получает полное
состояние. `applySessionLockAll` блокирует только запираемых потомков любого
узла с детьми; `applySessionUnlock` открывает ровно одну точку.

Команды `lockAll` / `unlock` идут в уже существующем `session.updateRates`
(проверка владельца комнаты на сервере сохранена), кнопка «Заблокировать всё»
— в живой панели Мастера, парные строки RU/EN.

### 3. Адресный взлом без каскада

Точка, открытая чужим событием через явную ссылку «ИЛИ», больше **не**
становится новым источником: событие порождает только найденный ключ или
собственная мини-игра. Исторический тест 517 приведён к новому закону.
Ключ по-прежнему можно назначить многим точкам — каждая открывается им
независимо, поточечно.

### 4. Общие состояние и ресурсы локации

Реестр хранит **один объект сессии** и рассылает его всем комнатам из
`roomCodes` (`boundRooms`). Правки, взятие добычи, сделка и закрытие
обновляют состояние во всех привязанных комнатах; комната без кода в списке
не видит локацию вообще. Протокол и лимиты сообщений не менялись.

### 5. Одна сессия и навигация

Узлы и сессия несут `parentIds`, `childIds`, `depth`, `roomCodes`;
`linkedCheckIds` на уровне сессии больше не теряется, вложенная локация
сохраняет `kind: 'hub'`. Игрок ходит по стеку вложенных локаций с кнопкой
«← Назад»; возврат к родителю сессию не гасит. «Покинуть локацию» сбрасывает
стек и отключает только этого игрока.

## Проверка

```bash

cat public/version.json     # "version": "523"
```

Приёмочный тест `__tests__/room/location-graph-523.test.js` проверяет циклы,
несколько родителей, наследование кодов, границу видимости, «заблокировать
всё», адресный взлом и общую сессию для двух комнат при невидящей третьей.

`patchs/baseline.json` = `523`, заметки релиза парные (91 / 91), `dist/`
пересобран. Живой план — `docs/roadmap.md`: тезис 13 в работе, оставшиеся
подпункты перечислены в разделе «Осталось после патча 523».

## Важно

Защита сервера, хранение склада, мини-игры взлома и механика предметов из 522
**не менялись**. Четыре технических допущения ассистента приняты по умолчанию
и записаны в спецификации; владелец может поправить их следующим обновлением.
