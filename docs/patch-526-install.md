# Установка патча 526: подходы игрока и решение Мастера

Патч подготовлен от состояния **версии 525** (коммит `2a0b3e0`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–526
цепочкой. Файл установки: `patchs/526-lock-attempts.patch`.

> Владелец: «То было сообщение на баг. Когда после успешного взлома, снова
> запускался взлом. Юзер может совершать сколько угодно подходов для вскрытия
> терминала/замка. Но только по своему усмотрению. Вот сейчас кончились
> отмычки, юзер купил новые и вернулся к взлому. Или прокачался и улучшил
> характеристики и снова решил попробовать силы... Терминал может запускать
> новую конфигурацию, а взлом замков нет. Терминал после провала получает
> статус "заблокировано", и можно ли повторно ПОСЛЕ БЛОКИРОВКИ взламывать —
> на усмотрение мастера. Если он разрешил, то можно взломать снова. Замки пока
> не блокировать, но в будущем будут, когда я придумаю условие блокировки».

## Что изменено

### 1. «Билет на один взлом» убран

`components/lootTrade/terminalAccess.js` больше не блокирует «Взломать» по
`used`/`accessId`: `canHackTerminal` игнорирует «ДОСТУП ИСПОЛЬЗОВАН»,
`terminalBlockedReason` не возвращает `'used'`. Из
`PlayerLootTradeOverlay.js` удалены `usedTerminalAccess`, `markTerminalAccess`
и отметки на карточках. Закрытое окно отдельно выданной точки превращается в
кнопку-пилюлю «Открыть» (или «свернутое» окно сессии), а не сжигает доступ.

`accessId` и `terminalAccessKey()` сохранены как идентификатор трансляции для
диагностики, дедупликации открытого окна и совместимости.

**Баг 506 остаётся исправленным:** автоматический рестарт после ACCESS
GRANTED невозможен — `shouldAutoStart` / `shouldAutoStartLock` не шлют `start`
в финальных статусах, сервер отклоняет `start` при `won` и активной доске.

### 2. Явный новый подход (`newAttempt`)

- `server/lockPicking.js`: `applyLockAction` понимает `newAttempt` и собирает
  свежую доску по текущему снимку листа (отмычки, PER, LOCKPICK, сложность,
  число ячеек), сохраняя `spentPins`.
- `server/roomRegistry.js`: `terminalAction` обрабатывает `newAttempt` после
  проверок роли `player`, членства, опубликованного листа и требования ключа.
  Действие снимает `closed`, не меняет `accessId`, не отзывает событие
  `hacked`. Для терминалов оно запрещено (`TERMINAL_NOT_ACTIVE`) — обойти
  блокировку после провала нельзя.
- `server/protocol.js` / `src/room/roomProtocol.ts`: код `LOCK_BLOCKED` для
  будущего условия блокировки.
- `components/lootTrade/localLockGame.js`: тот же закон в локальном резерве
  для старого сервера комнат.
- `components/lootTrade/LockPickingModal.js`: проп `freshAttempt` (из входной
  модалки и карточки локации) шлёт `newAttempt` вместо `start`; кнопка «Ещё
  подход» доступна в окне доски после победы, провала или «кончились отмычки».
- `components/lootTrade/lockAutoStart.js`: `freshAttempt` разрешает явный
  запуск в любом состоянии доски, но ровно один раз на монтирование окна.

### 3. Замки пока не блокируются

- Вместо «Ожидание решения Мастера» с «Да/Нет» — «Подход завершён», результат
  и «Ещё подход». Парные RU/EN строки: `lock.newAttempt`,
  `lock.approachFinished`, `lock.newAttemptHint`, `lock.stateOutOfPins`,
  `lock.hackedTitle`, `lock.hackedMessage`.
- `terminalRetryPrompt.js` не задаёт Мастеру вопрос по замку;
  `TerminalRetryPromptHost` поздравляет Мастера отдельным текстом для замка.
- `server/roomRegistry.js`: решение Мастера `retry` для замка отклоняется,
  `awaitingGm` у замка не выставляется; админ-панель
  (`LootTradeScreen.js`) показывает «Нет отмычек» без блокирующих кнопок.
- **Задел под будущее условие:** `LOCK_BLOCK_POLICY` и `shouldBlockLock()`
  в `server/lockPicking.js` (сейчас `{ enabled: false }`). Сервер, реестр и
  локальный резерв уже спрашивают её — когда владелец придумает условие,
  меняется одна функция.

### 4. Терминал не изменился

После провала — `awaitingRetry` («заблокировано»), вопрос Мастеру
«Разрешить повторный взлом? Да/Нет»; «Да» строит новую конфигурацию по
текущим настройкам и листу оператора, «Нет» закрывает до повторной
трансляции (`reissue`). После ACCESS GRANTED доска не пересобирается (505).

## Что сохранено

- Защита сервера: лимиты сообщений, проверки роли/владельца/членства,
  валидация JSON, целые положительные количества, атомарность переносов.
- Мини-игра 520 (PER, отмычки, четыре стрелки, «Да/Нет» у терминала),
  исправления 524 (один `start`, поиск отмычек, локальный резерв), 525
  (входная модалка, светлая гамма, «Покинуть локацию» в настоящей локации).
- Законы 522 (единый предмет, без игровых лимитов) и 523 (граф, граница
  видимости, адресный взлом, общие ресурсы).

## Проверки

- `npm run typecheck`, `npm run build`, `npm test` (полный набор).
- `git apply --check patchs/526-lock-attempts.patch` от дерева 525.
- `./apply-patch.sh 526` от версии 525 и полная цепочка 493–526 от чистого
  `main` `a62ec71`; побайтовое сравнение установленных деревьев.
- Приёмочные тесты: явный `newAttempt` после победы и после публикации нового
  листа (PER 4→10, отмычки 5→12), сколько угодно подходов подряд, запрет
  автоматического `start` после `won`, запрет `newAttempt` для терминала,
  «Нет» Мастера не закрывает замок, «Подход завершён» без «Да/Нет».
- Живой сервер комнат: `/version.json` = 526/4/97+97 и WS-проба.
- После установки на боевой площадке перезапустить процесс сервера комнат,
  чтобы подхватить обновлённые файлы `server/`.
