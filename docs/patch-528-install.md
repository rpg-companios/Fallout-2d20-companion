# Установка патча 528: команды списания и пауза перед сбросом цветов

Патч подготовлен от состояния **версии 527** (коммит `90cdeaf`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–528
цепочкой. Файл установки: `patchs/528-char-spend-commands.patch`.

> Владелец: «Заколки удаляются не из снапшота, а клиенту посылается команда на
> списание заколки из инвентаря, штатными средствами. И после списания
> посылается команда на обновление снапшота. Так не проще?» И: «Если ячейка
> красится в красный и заколка ломается, сделай небольшую паузу перед
> обновлением цветов. Но если заколка не сломалась, красный остается».

## Что изменено

### 1. Сервер перестал править чужой инвентарь

- `server/roomRegistry.js`: при росте `brokenPins` больше НЕ вызывается
  `consumeBobbyPins()` для `room.lastSnapshots`. `terminalAction()` возвращает
  `pinsToSpend` (дельту), `characterId` и `clientId`. Неподтверждённые команды
  живут в `room.pendingPinSpends`, `putSnapshot()` их снимает, `room.state`
  отдаёт `pendingSpends` для повтора после реконнекта. Новые методы:
  `registerPinSpend()` и `pendingSpendsForClient()`.
- `server/roomServer.js`: новый `sendPinSpendCommands()` шлёт оператору два
  кадра подряд — `char.spend` (spendId, characterId, itemId, count) и
  `char.refresh` (spendId, characterId). Порядок кадров WebSocket
  гарантирован. При `room.join` неподтверждённые команды повторяются.
- `server/protocol.js` / `src/room/roomProtocol.ts`: `CHAR_SPEND`
  (`char.spend`) и `CHAR_REFRESH` (`char.refresh`). Лимиты сообщений, проверки
  роли/членства и валидация не ослаблены.
- `consumeBobbyPins()` остался чистым помощником: его использует клиентский
  резерв для легаси-форм снимка и приёмочные тесты.

### 2. Клиент применяет команды штатными средствами

- `src/room/roomStore.ts`: подписка `onRoomCharSpend` для обоих кадров.
- `components/lootTrade/CharSpendCommandHost.js` (новый, смонтирован в
  `App.js` поверх всех экранов): `char.spend` → `spendBobbyPins()` вызывает
  `useCharacterStore.spendItemStacks` и `saveCharacter()` **без** публикации;
  `char.refresh` явно дожидается списания и публикует лист штатным
  `pushSavedCharacterToBoundRoomIfAny()` → обычный `char.publish`.
  `spendId` дедуплицируется (память + AsyncStorage): повтор команды после
  реконнекта не спишет заколку дважды. Команда чужому персонажу или с другим
  `itemId` игнорируется.
- `components/lootTrade/spendBobbyPins.js`: опция `publish: false` для
  сетевого режима; в локальном резерве лист публикуется как раньше.
- `components/lootTrade/LockPickingModal.js`: эффект списания оставлен
  **только** для локального резерва старого сервера, чтобы не было двойного
  вычета.

### 3. Пауза перед обновлением цветов

- `server/lockPicking.js`: константа `BREAK_HIGHLIGHT_MS = 650`; на поломке
  `breakHighlight = { durationMs: 650 }`, красный «?» в `cells` сохраняется;
  следующее нажатие снимает метку и стирает старые красные ячейки.
  `publicLockGameState()` пробрасывает метку клиенту и зрителям.
- `components/lootTrade/LockPickingModal.js`: `breakRedFaded` гасит красный
  только по истечении `durationMs`; `holdBoard` удерживает доску на экране на
  время паузы, даже когда заколки кончились. Без `breakHighlight` красный
  остаётся до следующего нажатия.
- `components/lootTrade/localLockGame.js`: локальный резерв доски отдаёт метку
  через тот же `publicLockGameState`.

## Что сохранено

- Защита сервера: лимиты сообщений, роли/владелец/членство, валидация JSON,
  целые положительные количества, атомарность переносов.
- Законы 520–527: PER/Удача/LOCKPICK, четыре попытки терминала, сколько
  угодно явных подходов игрока, запрет автоматического рестарта после ACCESS
  GRANTED, «Да/Нет» Мастера только для терминала, `shouldBlockLock()`,
  светлая гамма и входная модалка 525, канон «Заколка», затемнённая область
  стрелок, точная подсказка и красная ошибка 527.
- Законы 522 (единый предмет, без игровых лимитов, поля не обрезаются) и 523
  (граф, граница видимости, адресный взлом, общие ресурсы).
