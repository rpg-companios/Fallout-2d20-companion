# Установка патча 548: стрелки перемещения в админке

Патч подготовлен от состояния **версии 547**. Файл установки:
`patchs/548-admin-reorder-arrows.patch`.

> Баг владельца: «стрелки перемещения в админке не активны, возможно после
> выдачи и взлома замка на локации».

Предположение о выдаче и взломе не подтвердилось: ручка перетаскивания в дереве
локации была мертва **всегда**, с патча 545. Но на том же пути выдачи нашёлся
второй, настоящий дефект — подпись замка Мастера затиралась техническим
маркером. По слову владельца в 548 исправлены оба.

## Причина №1: жест захватывался раньше, чем задавался контекст

Ручка отдавала `onStartShouldSetPanResponderCapture: () => true`, а данные
строки (`parentId`, `childId`, список братьев) писала только в
`onStartShouldSetPanResponder`.

Система ответственности RN опрашивает **фазу перехода** сверху вниз и принимает
решение сразу, как только обработчик вернул `true`; фаза всплытия после этого не
опрашивается вовсе. Подтверждено по коду:

- `react-native-web/dist/modules/useResponderEvents/ResponderSystem.js`,
  `findWantsResponder` — цикл `// capture` возвращает результат немедленно;
- `react-native-web/dist/vendor/react-native/PanResponder/index.js` —
  `onStartShouldSetResponderCapture` вызывает
  `config.onStartShouldSetPanResponderCapture`.

Итог: контекст оставался `null`, `onPanResponderGrant` выходил по проверке
`if (!context) return`, перетаскивание не начиналось никогда.

Тест 545 этого не увидел, потому что вызывал обработчик всплытия руками —
живой браузер так не делает. Новый тест опрашивает фазы в настоящем порядке.

## Причина №2: маркер вместо подписи замка

Обратная запись живой сессии брала `lockLabel` узла как есть, а узел несёт
технический маркер для старого сервера комнат. Проверено на живом коде:
`«Ржавая дверь»` → `F2D20-LOC:{"v":1,"k":"loot","p":["town"],...}`.
Маркеры бывают вложенными: у замка внутри локации это
`F2D20-LOC:` → `F2D20-LOCK:` → текст в поле `l`.

## Границы

- Канон порядка 545 не тронут: источник истины — `childOrder` родителя и
  `server/locationGraph.js`; несколько родителей держат независимый порядок.
- Стрелки карточек сетки не менялись: их обработчик нажатия читает сам
  контейнер, а не контекст строки дерева, и работал верно. Это закреплено тестом.
- Флаг замка (`locked`) синхронизируется как раньше — правило преграды 546 и
  оконечность победы 547 не тронуты.
- Разбор подписи только читает: обычный текст возвращается без изменений,
  битый маркер не роняет чтение и остаётся как есть.
- Сервер комнат обновлять не нужно: обе правки клиентские.
