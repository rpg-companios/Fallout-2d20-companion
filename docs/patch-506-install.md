## Что изменилось

Владелец тестировал **в одном браузере в двух вкладках** и сообщил: «я во
вкладке мастера не вижу уведомление, что терминал взломан. А игроком я могу
закрыть терминал и останется окно терминала, но по факту оно считается окном
локации. И поскольку это активное окно локации я могу терминал взломать ещё
раз и ещё и ещё. Тут видимо архитектурный баг. Терминал не должен открываться
снова. И игроки должны иметь возможность сами отключаться от локации по
кнопке "покинуть локацию". Предлагаю её разместить рядом с кнопкой "свернуть"
в модалке».

### 1. Уведомление Мастера больше не теряется

Глобальный хост `TerminalRetryPromptHost` отбирал события только по
`room.role === 'gm'` в сторе. UI-режим вкладок одного браузера общий
(`localStorage`), поэтому вкладка владельца легко оказывалась с ролью
`player`: молчал и вопрос «Разрешить повторный взлом?», и сообщение
«Терминал взломан». Проверено рендер-тестом: при `role: 'gm'` алерт
вызывается, при `role: 'player'` — нет.

- `terminalRetryPrompt.js`: новый `isGmRoom(room, clientId)` считает комнату
  мастерской и по `role: 'gm'`, **и** по участнику с `role: 'gm'` и `clientId`
  этой вкладки. Список участников присылает сервер, он не зависит от
  переключателя «Пользователь / Админ».
- `findPending()` и `findCompleted()` принимают `clientId`; хост передаёт его
  из стора.
- Загрузка `ownerToken` из локальной БД обёрнута в `Promise.race` с
  секундным ограничением: зависшая транзакция больше не блокирует очередь диалогов.
- В `App.js` `<UpdateNoticeModal />` теперь смонтирован **до** `<AlertHost />`:
  окно «Что нового» после обновления больше не перекрывает уведомление.

### 2. Терминал не открывается снова

Признак «терминал открыт» жил в `useState` модалки — закрыл окно, состояние
исчезло, и кнопка «Взломать» в окне локации снова считала терминал
свободным. Это и был архитектурный дефект: состояние игрового доступа
принадлежало экрану, а не домену.

- **Сервер.** `terminalPublic` теперь отдаёт `accessId` — стабильный номер
  трансляции. Он создаётся при первой выдаче, **не меняется** на ходах, при
  правке карточки и при обычном `issueTerminal`, но обновляется после
  `reissue`, повторной выдачи локации (`openSession`) и ответа Мастера «Да».
- **Клиент.** Чистый модуль `components/lootTrade/terminalAccess.js` даёт
  `terminalAccessKey`, `canHackTerminal` и `terminalBlockedReason`.
  `PlayerLootTradeOverlay` запоминает израсходованный билет в своём состоянии
  (а не в модалке): первое нажатие «Взломать» блокирует кнопку до новой
  трансляции, а после `won` / `awaitingRetry` / `closed` блокируются **обе**
  кнопки с отметкой «Взломан» / «Ожидает решения» / «ЗАКРЫТ» /
  «ДОСТУП ИСПОЛЬЗОВАН». Наблюдать за активной доской по «Смотреть» до взлома
  по-прежнему можно.
- Та же одноразовость применена к терминалу, выданному напрямую: после
  закрытия плашка «Открыть терминал» больше не возвращает в мини-игру.

### 3. «Покинуть локацию» рядом со «Свернуть»

Раньше `playerCloseSession` явно запрещал игрокам закрывать `hub` («Локацию
может закрыть только Мастер»), а внешнее окно локации предлагало только
«Свернуть».

- В шапке внешнего окна локации добавлена кнопка **«Покинуть локацию»**
  (`testID="leave-hub-button"`) рядом с **«Свернуть»**.
- `leaveLocation()` вызывает `playerCloseRoomSession`; сервер для `hub`
  теперь добавляет `clientId` в `session.closedByClientIds`, **не гасит**
  сессию и рассылает обновление всем. `matchedContext` оверлея уже читает это
  поле — окно исчезает только у ушедшего игрока.
- Сцену целиком по-прежнему закрывает только Мастер; `lastClosedSession` для
  локации не создаётся. Подсказка под списком узлов обновлена.
- Парные RU/EN подписи: `player.leaveHub`, `player.leaveHubHint`, обновлённый
  `player.hubMasterClosesHint`, `terminal.accessUsed`.

## Установка

С действующей версии 505:

```bash
./apply-patch.sh 506
# ✓ Установлен патч: №506 (версия 505 → 506)
```

С чистого `main` со старым установщиком:

```bash
git fetch origin arena/054e6676-fallout-2d20-companion
sed -i 's|arena/c1c60b87-fallout-2d20-companion|arena/054e6676-fallout-2d20-companion|' apply-patch.sh
./apply-patch.sh 506
```

`patchs/baseline.json` в источнике равен `506`. После установки
`public/version.json` → `506`; закоммитьте изменения, **перезапустите сервис
Node.js** (новое поле `accessId` и правило выхода из локации живут на
сервере) и пересоберите веб-сборку. Уже открытые партии начните заново.

## Проверка

```bash
npm run typecheck
npx vitest run __tests__/room/terminal-access-506.test.js
npx vitest run __tests__/room/room-server.integration.test.js
npx vitest run
CI=1 EXPO_NO_TELEMETRY=1 NODE_ENV=production npm run build
curl -s http://localhost:5000/version.json | grep '"version": "506"'
```

Приёмочный тест `__tests__/room/terminal-access-506.test.js` покрывает: чистое
правило одного «Взломать» на билет, блокировку финальными статусами,
стабильность `accessId` на ходах и правке карточки, смену после `reissue` и
повторной выдачи локации, определение владельца по участнику (вкладка с
ролью `player` получает уведомление), приоритет `AlertHost`, порядок
«Покинуть локацию» рядом со «Свернуть» и парность словарей. WS-тест
проверяет, что после ухода первого игрока сессия остаётся активной для
второго, а `reissue` выдаёт новый `accessId`.
