# Установка патча 527: заколки, стрелки и честное списание

Патч подготовлен от состояния **версии 526** (коммит `4f8982a`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–527
цепочкой. Файл установки: `patchs/527-bobby-pins-ui.patch`.

Четыре замечания владельца к мини-игре замка: (1) русское имя
`item_bobby_pin` — «Заколка», а не «шпилька» / «отмычка» / «булавка»;
(2) на ПК и телефоне стрелки пересекают линии, слишком близко и непонятно,
нужна чуть более тёмная залитая область, более выраженные стрелки, чуть
большее расстояние и точная подсказка под счётчиком; (3) потраченные /
сломанные заколки должны исчезать из инвентаря, а не только из памяти
комнаты; (4) при ошибке знак `?` не красный.

## Что изменено

### 1. Терминология

- `modules/fallout/i18n/ru-RU/data/equipment/general_goods.json`:
  `item_bobby_pin.name` = **«Заколка»** (было «Шпилька»).
- `i18n/ru-RU/screens/lootTrade/screen.json`: все строки замка говорят
  «заколки/заколка» (`pins`, `noPins`, `noPinsHint`, `newAttemptHint`,
  `arrowsHint`). `i18n/en-EN/screens/lootTrade/screen.json` — парные строки.
- `item_electronic_lockpicker` остаётся **«Электронная отмычка»**: это другой
  предмет, он не считается заколкой и в мини-игре не участвует.
- Исторические примечания `public/version.json` и спецификация
  `docs/lockpicking-mini-game-design.md` приведены к тому же канону; раздел 13
  спецификации явно оговаривает, что слова «шпилька», «булавка», «отмычка»
  к `item_bobby_pin` не относятся.

### 2. Область стрелок и подсказка

- `components/lootTrade/lockPickingStyles.js`: новый `arrowPad` (заливка
  `ADMIN_MODAL_PALETTE.surfaceMuted` — чуть темнее карточки `surface`),
  кнопки `arrowButton` ещё на ступень темнее (`#dadada`), иконки `30`,
  `crossRow.gap = 16` вместо `8`, между рядами `marginVertical: 5`.
  `cellRed` / `cellTextRed` дают явный красный `#c1121f`.
- `components/lootTrade/LockPickingModal.js`: содержимое окна обёрнуто в
  `ScrollView` (на телефоне текст больше не накладывается на доску), под
  счётчиком `lock.pins` выведен `testID="lock-arrows-hint"` с точным текстом
  владельца, блок стрелок помечен `testID="lock-arrow-pad"`, иконки крупнее.
- Точный RU-текст (EN-пара `lock.arrowsHint`):

  > Нажимайте на стрелки. Верный вариант будет выделен зелёным цветом, ошибочный красным. Если вы ошиблись, попробуйте другой вариант. Если сломалась заколка взлом необходимо начать сначала.

- `docs/ui-modals-rules.md`: правило «не изобретать новый каркас, брать
  ближайший» дополнено уточнением 527 (вложенная залитая область, а не новая
  модалка).

### 3. Сломанная заколка уходит из инвентаря

- `server/lockPicking.js`: экспортируется `consumeBobbyPins(snapshot, count)`.
  Он клонирует снимок, находит заколки во всех формах (`items`,
  `equipment.items`, `inventory`, `bag`, обёртка `data`, вложенные
  `item`/`snapshot`/`data`), уменьшает `quantity`/`count`/`qty`/`amount` или
  удаляет опустевшую стопку, дедуплицирует один экземпляр по `instanceId` и
  не трогает остальные поля предмета (закон 522). Исходный снимок не мутируется.
- `server/roomRegistry.js`: при каждом росте `brokenPins` вызывается
  `consumeBobbyPins()` для `published.snapshot`, обновлённый лист кладётся в
  `room.lastSnapshots` и в `entry.operatorSnapshot`, затем рассылается обычным
  состоянием комнаты. `pinLedger` остаётся только диагностикой; при сборке
  доски `spentPins` теперь всегда `0`, поэтому двойного вычета нет.
- `components/lootTrade/spendBobbyPins.js` (новый): клиент зеркально списывает
  дельту из живого `useCharacterStore` через атомарный `spendItemStacks`, с
  резервом для легаси-сейвов через тот же серверный канон, затем
  `saveCharacter()` и `pushSavedCharacterToBoundRoomIfAny()`. Работает и в
  локальном резерве доски.
- `components/lootTrade/localLockGame.js`: `spentPins: 0` при сборке доски —
  заколки читаются из уже обновлённого листа, а не из счётчика.
- `components/lootTrade/LockPickingModal.js`: эффект на дельту `brokenPins`
  вызывает списание только у оператора доски; первое наблюдение за уже
  начатой партией лишь запоминает базу, чтобы перезагрузка страницы не
  списала заколки повторно.

### 4. Красный «?»

- `server/lockPicking.js`: перед каждым нажатием прежние `red`-ячейки
  очищаются (ровно одна красная ошибка), а на ходе с поломкой заколки текущая
  красная ячейка **сохраняется** — раньше при навыке 0 красный «?» стирался
  сразу и игрок не видел ошибку.
- `components/lootTrade/lockPickingStyles.js`: `cellTextRed` — `#c1121f`,
  жирный и крупнее обычного знака; `cellRed` — розовая заливка с красной
  рамкой.

## Что сохранено

- Защита сервера: лимиты сообщений, проверки роли/владельца/членства,
  валидация JSON, целые положительные количества, атомарность переносов.
- Законы 520–526: PER/Удача/LOCKPICK, четыре попытки терминала, сколько
  угодно ЯВНЫХ подходов игрока, запрет автоматического рестарта после ACCESS
  GRANTED, «Да/Нет» Мастера только для терминала, `shouldBlockLock()` как задел
  под будущую блокировку замков, входная модалка и светлая гамма 525,
  «Покинуть локацию» в настоящей локации.
- Законы 522 (единый предмет, без игровых лимитов, поля не обрезаются) и 523
  (граф, граница видимости, адресный взлом, общие ресурсы).
