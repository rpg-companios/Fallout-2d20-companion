# Словарь мини-игры взлома терминалов

Данные собраны из EOWL фильтром узнаваемости ESDB/SCOWL и разложены по **шести файлам —
по одному на длину слова**. Длина слова = эффективная сложность терминала + 4,
поэтому нужный файл известен ещё до того, как строится доска.

- Генератор: `scripts/build-terminal-words.mjs`
- Входные данные (только сборка): `scripts/terminal-words/`
- Готовые файлы (рантайм): `server/terminalWords/`
- Загрузчик: `server/terminalWords/index.js`
- Лицензии и уведомление UKACD: `scripts/terminal-words/LICENSES.md`
- Обоснование правил баланса: `docs/terminal-hacking-balance-proposal.md`

## Почему не один большой файл

Уточнение к обсуждению: **1,1 МБ не «плохо для UI»** — интерфейс этот файл не
рисует. Реальная цена одного общего файла другая:

| | весь EOWL одним файлом | шесть файлов по длине |
|---|---|---|
| В бандле | +1,1 МБ | +152 КБ всего, ~14–30 КБ за раз |
| Парсинг при старте | 128 977 строк, ~50–100 мс на телефоне | один массив 1 400–2 500 строк |
| Память | ~5–10 МБ под строки | ~0,2 МБ на один загруженный список |
| Смысл | 90 % слов никогда не нужны (длины 1–3, 10, редкости вроде `aalii`) | берём ровно длину `d + 4` |

Но главное: **фильтрация большого файла в рантайме вообще не происходит**.
Генератор один раз на машине разработчика читает 1,1 МБ, отсекает редкости и
ругань и записывает шесть маленьких JSON. Приложение получает только результат;
ни EOWL, ни ESDB/SCOWL в бандл не попадают (`scripts/` — входные данные
сборки). Поэтому «сразу брать нужный список» — ровно то, что реализовано:

```js
const { getWordsForDifficulty, getWordsByLength } = require('./server/terminalWords');

const words = getWordsForDifficulty(5); // → words-9.json, 1 965 слов
// или напрямую: getWordsByLength(9)
```

`require()` спрятан в ветку `switch`-подобной карты со статическими путями:
Metro видит зависимости, но выполняет их лениво, при первом обращении.

## Что получилось

| сложность | букв | файл | слов | размер | анаграммных семей (макс. размер) |
|---:|---:|---|---:|---:|---:|
| 0 | 4 | `words-4.json` | 1 405 | 13,7 КБ | 177 (6) |
| 1 | 5 | `words-5.json` | 1 902 | 20,4 КБ | 123 (5) |
| 2 | 6 | `words-6.json` | 2 478 | 29,0 КБ | 119 (4) |
| 3 | 7 | `words-7.json` | 2 387 | 30,3 КБ | 63 (3) |
| 4 | 8 | `words-8.json` | 2 171 | 29,7 КБ | 22 (3) |
| 5 | 9 | `words-9.json` | 1 965 | 28,8 КБ | 11 (2) |
| | | **всего** | **12 308** | **~152 КБ** | |

`manifest.json` содержит те же счётчики, источники и ссылку на лицензию.

Для сравнения: прежний встроенный список движка — 34–64 слова на длину, из-за
чего два-три терминала подряд получали почти одинаковые доски. Теперь запас в
25–65 раз больше. Точные анаграммы с ростом длины, наоборот, редеют (177 → 11
семей), поэтому доска сложности 5 строится на **похожих словах и общих
окончаниях**, а не на точных перестановках — как и договаривались.

## Как устроен фильтр

1. `eowl-words.txt` — 128 977 настоящих слов; оставляем `[a-z]+` длиной 4–9.
   Никаких выдуманных слов: `stuff` есть, `stoof` отсутствует.
2. `scowl-common-35.txt` — 12 650 слов ESDB/SCOWL размера `<= 35` (базовая
   полоса «обычных» слов). Пересечение убирает редкости, которые игрок принял
   бы за опечатку (`aah`, `aalii`, `acta`). Источник прямо разрешает
   коммерческое использование, в отличие от частотного списка Google, который
   был исключён.
3. Чёрный список (`filter.json`) — наш перечень ругани и тяжёлых тем.
4. Белый список — прежние 282 слова мини-игры, примеры владельца
   (`steps`, `drops`, `cross`, `score`, `course`, `foots`, `boots`, `boost`,
   `stuff`, `dice`, `post`, `spot`, `stop`, `pots`, `tops`, `opts`) и
   `afterlife`: реальное слово, которого нет в UKACD (учтено в
   `verifiedNonEowl`). Генератор падает, если в белый список попал слово,
   которого нет ни в EOWL, ни в `verifiedNonEowl`.
5. Дополнительный чёрный список качества: редкости (`abba`, `acta`, `aero`), личные имена и тяжёлые темы (`abortion`, `suicide`) — чтобы доска выглядела нейтральной головоломкой.
6. Сортировка, дедупликация, верхний регистр, проверка формата `^[A-Z]{len}$`.

## Перегенерация

```bash
node scripts/build-terminal-words.mjs          # записать шесть JSON + manifest
node scripts/build-terminal-words.mjs --check  # сверить с диском (использует тест)
```

Генерация детерминирована: те же входные файлы дают побайтно те же выходные.
`__tests__/room/terminal-words.test.js` сверяет файлы с генератором и проверяет
инварианты (формат, уникальность, отсутствие `STOOF`, примеры владельца).

Словарь собран, проверен и **подключён к движку**: `server/terminalHacking.js`
берёт слова через `getWordsByLength()` (совместимый экспорт `WORDS_BY_LENGTH`
реализован ленивыми геттерами). Генератор доски, лестница похожести, режим
`d=0`, таблицы ИНТ/Науки/Удачи, удаление служебной строки и окно
«О приложении» — всё в патче 495.

Уведомление UKACD «prominently displayed» теперь выведено **в самом
приложении**: окно «О приложении / Благодарности» содержит официальный
дисклеймер, AGPL для движка и дословные тексты UKACD и ESDB. Это важно для
планируемой коммерческой версии.
