# Перевод + фикс — обшивки/рамы/броня роботов (применено)

**Проблема:** у обшивок, рам и брони роботов было **одно общее название для всех частей тела**
(«Стандартная обшивка», «Заводская рама» …). В интерфейсе (`ArmorLayerModal`,
`ArmorPickerModal`) рядом с названием часть тела не выводится — поэтому обшивка на руке и
на корпусе выглядели одинаково.

**Решение:** к названию добавлено уточнение части тела: `«<Название> для <части>»`.

## Соответствие локаций и частей тела

В данных 4 бронелокации (`robotLocation`). Каждая едина для всех роботов, но анатомически
означает разное у разных планов тел — поэтому термины подобраны нейтрально:

| robotLocation | Часть тела (RU)          | (EN)                | Что это у разных роботов |
|---|---|---|---|
| Optics    | **для головы (оптики)** | for the Head (Optics) | глаз-стебелёк (Помощник) / настоящая голова (остальные) |
| Main Body | **для корпуса**         | for the Body          | тело/корпус — у всех одинаково |
| Arms      | **для руки** (ед.ч.)    | for the Arm           | руки/манипуляторы — у всех |
| Thruster  | **для ходовой части**   | for Locomotion        | движитель (Помощник) / шасси-гусеницы (Робомозг) / ноги (Протектрон, Штурмотрон, Турель-бот) |

- **Optics → «голова (оптика)»:** у Мистера Помощника это eye-stalk (`robot_head_mister_handy_eye_stalk`, без `mind`), у остальных — настоящая голова. «Голова (оптика)» покрывает оба случая.
- **Thruster → «ходовая часть»:** слоты `thruster`/`chassis`/`leftLeg`/`rightLeg` мапятся в одну локацию `Thruster` (`SLOT_LOCATION_MAP`). Нейтральный термин верен для движителя, шасси и ног.

## 1. Обшивки (`i18n/…/robot/plating.json`) — 28 строк
Сохранено различие «обшивка / плита» (Plating / Plate в оригинале).

| id-шаблон | RU → |
|---|---|
| `robot_plating_standard_*`   | Стандартная обшивка для **головы (оптики) / корпуса / руки / ходовой части** |
| `robot_plating_gutsy_*`      | Обшивка Мистера Храбреца для **…** |
| `robot_plating_factory_*`    | Заводская обшивка для **…** |
| `robot_plating_primal_*`     | Первобытная плита для **…** |
| `robot_plating_serrated_*`   | Зубчатая плита для **…** |
| `robot_plating_noxious_*`    | Ядовитая плита для **…** |
| `robot_plating_toxic_*`      | Радиоактивная плита для **…** |

## 2. Рамы (`i18n/…/robot/frames.json`) — 12 строк

|---|---|
| `robot_frame_actuated_*`  | Раздвижная рама для **…** |
| `robot_frame_voltaic_*`   | Вольтовая рама для **…** |

## 3. Броня роботов (`i18n/…/robot/armor.json`) — 5 строк
| id | RU → |
|---|---|
| `robot_armor_factory_*` | Заводская броня для **головы (оптики) / корпуса / руки / ходовой части** |
| `robot_armor_storage_body` | **без изменений** — «Заводская броня с хранилищем» (только корпус, название уже уникально) |

`…` = головы (оптики) / корпуса / руки / ходовой части.

## 4. Бонус-фикс данных: дефолт головы Мистера Помощника

В `data/bodyplans/bodyplans.json` дефолт `misterHandy.head` указывал на несуществующий id
`robot_head_mister_handy` — реально в `robotheads.json` есть только `robot_head_mister_handy_eye_stalk`.
Раньше это работало лишь благодаря фолбэку в `domain/robotEquip.js` (`defaultForBodyPlan`).

Исправлено:
```diff
-      "head": "robot_head_mister_handy",
+      "head": "robot_head_mister_handy_eye_stalk",
```
Наборы экипировки (`data/equipmentKits/misterHandy.json`) уже использовали правильный id.

## Что менялось технически
- i18n: только поля **`name`** в ru-RU и en-EN (6 файлов).
- Данные: 1 строка в `data/bodyplans/bodyplans.json` (фикс id головы).
- `id`, статика и остальная логика — не тронуты; поля `special` — без изменений.
- Проверено: JSON валиден, `id` совпадают с данными в обеих локалях, битых ссылок на
  `robot_head_mister_handy` не осталось.
