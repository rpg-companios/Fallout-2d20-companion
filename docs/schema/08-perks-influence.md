# Влияние перков на программу — классификация (ЧЕРНОВИК)

Статус: **черновик к ревью владельцем**. Правила процесса (от владельца):
контекст и лор перка оценивает только владелец; правки классификации и
любое создание механик-модификаторов — **только совместно с владельцем**.
Этот документ — инвентаризация, а не проектирование: механики не
закладываются до ответов на вопросы §5.

Источник данных: `data/perks/perks.json` (94 перка), описания —
`i18n/ru-RU/data/perks/perks.json`.

## 1. Что приложение считает сегодня (карта «влияет»)

Механика считается влияющей, если она садится на систему, которая УЖЕ
считается приложением:

- **Атрибуты S.P.E.C.I.A.L.** — `attributes` (редактируемы; перк-режим).
- **Навыки** — ранги навыков, очки навыков.
- **Производные** — `calculateDerivedStats` (`src/store/resolvers.js`):
  `maxHealth`, `initiative`, `defense`, `meleeBonus`, `carryWeight`,
  `damageResistance` (физ/энер/рад).
- **ОЗ, радиация, удача, крышки** — состояния стора.
- **Эффекты** — timed-эффекты с длительностью; пайплайн `perkBonuses`
  уже влит в производные.
- **Силовая броня** — надетый пакет, прочность частей, заряды Ядерных
  блоков.
- **Экономика** — модалки покупки/продажи реально считают цену.
- **Модификации** — установка модов оружия/брони реализована (без гейта).

Чего в приложении НЕТ (значит, не влияет): броски проверок навыков/d20,
ОД-пул и экономия действий, ход бой-встречи, NPC/компаньоны, лут/находки,
журналы как механика, зависимости, среда/время/погода.

## 2. Существующая архитектура перков

`data/perks/perks.json` → поле `effect` — флаг-ид эффекта. Реестр
механик: `domain/perks/index.js` (`perkEffects`), модули-эффекты с
`apply(ctx) → bonuses`. Агрегация: `calculatePerkEffects` →
`perkBonuses` в сторе → влито в `calculateDerivedStats` как слой эффектов.

Реализовано 3 из 94: `intenseTraining`, `educated` (каркасно), `snakeater`.
Остальное — флаги-лейблы: UI показывает текст без механики (как
`effects` у черт, см. `07-trait-debt.md`).

Целевое направление (от владельца): **каждый перк — механика через свой
JSON**. Форма JSON-контракта — отдельное обсуждение ПОСЛЕ утверждения
этой классификации (ориентир — 06-modifiers + существующие effect-модули).
