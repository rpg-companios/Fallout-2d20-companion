# Установка патча 504: решение Мастера вместо блокировки после провала

Патч подготовлен от состояния **версии 503** (коммит `13f2ff6`, ветка
`arena/054e6676-fallout-2d20-companion`). Применим и к чистому `main`
`a62ec7109b50ad720641a4fdeb48f1de865d8742` — установщик подтянет 493–504
цепочкой.

## Что изменилось

Владелец заменил прежнюю модель: «вместо "блокировать после провала"
переходим на модель: мастеру всплывает сообщение "Разрешить повторный взлом?
Да/нет". Если да — новый конфиг. Нет, терминал нельзя больше взломать или
посмотреть, если мастер не транслирует его снова».

Уточнения: вопрос задаётся **только когда попытки исчерпаны** (после успеха —
нет); «Да» **сразу** строит новую доску по **текущим настройкам** карточки;
«Нет» оставляет карточку видимой с отметкой **«Закрыт»**, запрещая и
«Взломать», и «Смотреть» до новой трансляции; галочка `lockOnFailure`
удаляется из формы, движка и сохранений **полностью**.

### 1. Провал больше не тихий и не автоматический

Раньше без галочки партия переходила в `failed` с пустым `result`, а игрок
мог просто нажать «Взломать» ещё раз — доска пересобиралась из старых полей,
без всякого решения Мастера. С галочкой терминал блокировался сам, без
вопроса.

Теперь в `server/terminalHacking.js`:

- `failGame()` всегда возвращает `status: 'awaitingRetry'` и
  `result: 'ATTEMPTS EXHAUSTED'`. В окне взлома видно «ВЗЛОМ ПРОВАЛЕН»,
  «Все попытки исчерпаны», «Ожидание решения Мастера».
- «Дайджест программиста» по-прежнему предлагает последнюю попытку **до**
  вопроса Мастеру; отказ от журнала тоже приводит к `awaitingRetry`.
- Любое действие игрока (`start`, `guess`, `bracket`, `view`, `useDigest`)
  в этом состоянии отклоняется с `TERMINAL_AWAITING_RETRY`. Повторный взлом
  без одобрения Мастера невозможен.
- `applyGameAction()` принимает свежий `config` на каждом ходу
  (`syncGameConfig`): имя и описание карточки обновляются без пересборки
  доски, а новая партия всегда собирается по текущим настройкам, а не по
  полям предыдущей доски.

### 2. Вопрос Мастеру поверх любого экрана

`components/lootTrade/TerminalRetryPromptHost.js` смонтирован один раз в
`App.js` рядом с `AlertHost` и следит за `terminalStates` всех комнат Мастера.
Когда сервер выставляет `awaitingGm: true`, всплывает диалог
**«Разрешить повторный взлом?»** с кнопками **«Да»** и **«Нет»**:

- имя терминала и сложность приходят из текущей карточки;
- несколько провалившихся терминалов обрабатываются по очереди;
- решение уходит действием `terminal.action` → `retry` со значением
  `yes` / `no`;
- закрыть диалог без ответа нельзя — вопрос повторится, пока Мастер не
  решит.

Чистая логика отбора (`findPending`) вынесена в
`components/lootTrade/terminalRetryPrompt.js` и покрыта тестами. Дубликаты
на одну и ту же ревизию партии не задаются повторно.

На экране «Добыча/Торговля» в админ-панели терминала те же **«Да» / «Нет»**
доступны и вручную, а состояние показывается как «Доступен» /
«Ожидает решения» / «Закрыт».

### 3. «Да» = новая доска по текущим настройкам

`retry: yes` — действие только Мастера (`TERMINAL_GM_ONLY` для игрока).
Сервер **сразу** вызывает `createGame()` с `entry.config`:

- новая сложность, имя и описание, если Мастер успел их поменять **во время
  доступа или уже после провала**;
- новые слова, подсказки и скобки, `revision` сброшен, догадки пустые;
- ровно **4 попытки**, ни одна скобка не использована;
- лист оператора сохранён: ИНТ 10 / Наука 6 дают 15 слов и 4 скобки, а не
  дефолтные 21 слово. Другой игрок может нажать «Взломать» затем и собрать
  доску уже под свой лист (механика передачи хода из патча 503 сохранена).

Правка настроек во время активной партии больше **не стирает** доску: игрок
не теряет прогресс, а новая сложность вступит в силу при следующей новой
партии.

### 4. «Нет» = «Закрыт» до новой трансляции

`retry: no` переводит партию в `status: 'closed'` и выставляет
`terminal.closed` (плюс `locked` как алиас для клиентов прежних версий):

- карточка терминала **остаётся на экране** с отметкой **«ЗАКРЫТ»**;
- обе кнопки — «Взломать» и «Смотреть» — отключены; прямой выданый
  терминал показывает плашку «ЗАКРЫТ» вместо окна взлома;
- сервер отвечает `TERMINAL_CLOSED` на любые действия игрока, включая
  попытку «посмотреть»;
- «Да» после отказа не обходит запрет: решение принимается только в
  состоянии `awaitingRetry`.

Снова открыть терминал можно **только новой трансляцией Мастера**: кнопка
«Транслировать заново» в админ-панели (`reissue`), повторная выдача
терминала («Выдать», `issueTerminal` с `reissue: true`) или повторная выдача
локации. Обычная правка карточки или узла локации «Закрыт» не снимает.

### 5. Галочка удалена полностью

- `ContainerFormModal`: нет ни состояния, ни чекбокса, ни строк стилей; в
  форме терминала осталась только сложность 1–5.
- `server/terminalHacking.js`, `server/roomRegistry.js`,
  `server/lootTradeSession.js`, `domain/lootTrade.js`: `lockOnFailure` и
  `nodeLockOnFailure` не читаются и не пишутся.
- Маркер `F2D20-TERM:` больше не содержит поле `f` (только `v`, `d`, `l`);
  старые маркеры с `f` читаются, но поле игнорируется — сохранения прежних
  версий не ломаются.
- Словари RU/EN: удалены `form.terminalLockLabel`,
  `terminal.terminalLockedHint`, `terminal.locked`, `terminal.available`,
  `terminal.unlock`; добавлены парные тексты вопроса, «Да»/«Нет»,
  «ЗАКРЫТ», ожидания и повторной трансляции.
- `src/room/roomStore.ts` больше не знает о `nodeLockOnFailure`; в протокол
  (`server/protocol.js`, `src/room/roomProtocol.ts`) добавлены парные коды
  `TERMINAL_CLOSED` и `TERMINAL_AWAITING_RETRY`.

### Локальный резерв

Если сервер комнат старой версии, партия идёт на устройстве игрока.
`localTerminalGame.js` повторяет ту же модель: провал → `awaitingRetry`,
в модалке всплывает тот же вопрос «Да/Нет» (Мастер за этим же устройством),
«Да» собирает свежую доску по текущим настройкам, «Нет» закрывает терминал.

## Что не менялось

Формула `N = max(4, 15 + 2·D − ИНТ)` (на D5 «25 − ИНТ»), `L = 4 + D`,
4 попытки, число и состав скобок по Науке, удача 5–20 % и не более одного
полного восстановления на доску, три группы слов с двумя вариантами, перк
«Хакер», чтение листа из сетевого сейва/экспорта/локального стора, смена
оператора по «Взломать», 12 308 слов словаря, терминал внутри локации
открывает окно взлома, а не сундук.

## Через `apply-patch.sh` (основной способ)

```bash
./apply-patch.sh 504
```

С чистого `main` со старым установщиком:

```bash
git fetch origin arena/054e6676-fallout-2d20-companion
sed -i 's|arena/c1c60b87-fallout-2d20-companion|arena/054e6676-fallout-2d20-companion|' apply-patch.sh
./apply-patch.sh 504
```

`patchs/baseline.json` в источнике равен `504`. После установки:
`public/version.json` → `504`; закоммитьте изменения и **перезапустите
сервис Node.js** (состояние партий и решение Мастера считаются на сервере),
пересоберите веб-сборку. Партии, начатые до обновления, запустите заново:
после установки сервер уже будет требовать ответа Мастера.

и WS-интеграция покрывают: явный провал и запрет повторного взлома, отсутствие

доступа и сохранением листа оператора, «Нет» с закрытием обеих кнопок,
повторную трансляцию, полное удаление галочки, парность словарей и кодов
ошибок, локальный резерв.
