# Дизайн: каталоги персонажей / Character folders

**Статус:** утверждённый дизайн, реализация в работе  
**Назначение:** организация сохранённых персонажей по пользовательским каталогам.

---

## 1. Цели

Каталоги позволяют пользователю группировать созданных персонажей, например по кампании, фракции, игроку или сценарию.

Функция должна:

- не менять текущий сценарий использования для тех, кто не создаёт каталоги;
- сохранять структуру между запусками приложения;
- позволять перемещать персонажа между каталогами жестом drag-and-drop;
- позволять вернуть персонажа в корневой список;
- поддерживать русский и английский интерфейс.

---

## 2. Настройка

В глобальном окне **«Настройки»** добавляется переключатель:

```text
Каталоги персонажей
Организуйте созданных персонажей по каталогам.

[ переключатель ]
```

English:

```text
Character folders
Organize created characters into folders.

[ switch ]
```

### Правила

- Настройка глобальная, не привязана к отдельному персонажу.
- По умолчанию выключена.
- При включённой настройке пользователь может создавать новые каталоги.
- При выключенной настройке уже созданные каталоги остаются видимыми и открываемыми.
- При выключенной настройке создание новых каталогов недоступно.
- Кнопка «Создать каталог» остаётся на месте, но отображается неактивной.
- Выключение настройки не удаляет каталоги, персонажей или их распределение.

---

## 3. Корневой экран персонажей

На экране списка персонажей используется сетка из трёх колонок.

Первая строка содержит три action-ячейки:

```text
[ + Создать ] [ ↑ Загрузить ] [ folder-plus-outline Создать каталог ]
```

Ниже располагаются:

1. карточки каталогов;
2. карточки персонажей, не принадлежащих ни одному каталогу.

Персонаж без каталога считается находящимся в корневом списке.

---

## 4. Создание каталога

При нажатии **«Создать каталог»**, если настройка включена, в следующей свободной ячейке появляется временная карточка:

```text
┌──────────────────────┐
│         📁           │
│ [Название каталога]  │
│                      │
│ [Создать] [Отмена]   │
└──────────────────────┘
```

### Правила ввода

- Поле получает фокус автоматически.
- Пустое название создать нельзя.
- Пробелы в начале и конце удаляются.
- Названия могут повторяться: уникальность обеспечивается внутренним `id` каталога.
- «Создать» сохраняет каталог.
- «Отмена» удаляет временную ячейку без изменений.

---

## 5. Карточка каталога

Пример карточки:

```text
┌──────────────────────┐
│         📁           │
│  Выжившие Мохаве     │
│  Персонажей: 4       │
└──────────────────────┘
```

Нажатие на карточку открывает отдельный экран каталога.

---

## 6. Экран каталога

Экран каталога содержит:

```text
← Название каталога
  Персонажей: N

[ карточка ] [ карточка ] [ карточка ]
```

На нём показываются только персонажи выбранного каталога.

Доступны обычные операции с персонажем:

- открыть;
- экспортировать;
- удалить;
- перенести в другой каталог;
- вернуть в корневой список.

---

## 7. Перемещение персонажей

### 7.1. Маркер захвата

В верхнем левом углу карточки персонажа отображается векторная иконка:

```text
arrow-all
```

Именно этот элемент является drag-handle.

- Нажатие на основную область карточки открывает персонажа как раньше.
- Нажатие на удаление и экспорт продолжает выполнять соответствующие операции.
- Drag-and-drop начинается только с `arrow-all`.

### 7.2. Перенос в каталог

1. Пользователь удерживает drag-handle.
2. Карточка поднимается над сеткой.
3. Карточки каталогов подсвечиваются как допустимые drop-зоны.
4. Пользователь отпускает карточку над каталогом.
5. Персонажу назначается `folderId` выбранного каталога.
6. Счётчик персонажей обновляется.

Если карточка отпущена вне допустимой зоны, перенос отменяется.

### 7.3. Возврат в корневой список

На экране открытого каталога доступна отдельная drop-зона:

```text
Вернуть в список персонажей
```

Drop на эту зону снимает `folderId` у персонажа. Он снова отображается в корневом списке.

---

## 8. Удаление каталога

Карточка каталога имеет кнопку удаления.

При удалении отображается подтверждение:

```text
Удалить каталог?

Будут безвозвратно удалены каталог «Выжившие Мохаве»
и все персонажи внутри него: 4.

[Удалить каталог и персонажей] [Отмена]
```

### Правило удаления

Подтверждённое удаление удаляет:

- каталог;
- всех персонажей, находящихся в нём;
- связи персонажей с каталогом;
- связанные локальные данные сохранений;
- связанные записи облачной синхронизации, если она включена.

---

## 9. Модель данных

Каталог является отдельной сущностью. Он не должен храниться внутри JSON конкретного персонажа, потому что каталог может быть пустым.

```js
{
  id: 'folder_...',
  name: 'Выжившие Мохаве',
  createdAt: 1760000000000,
  updatedAt: 1760000000000,
  sortOrder: 0
}
```

Принадлежность персонажа к каталогу:

```js
{
  characterId: 'char_...',
  folderId: 'folder_...'
}
```

Персонаж без записи принадлежности находится в корневом списке.

---

## 10. Хранение и синхронизация

Нужно поддержать данные каталогов в обоих окружениях:

- native / SQLite;
- web / AsyncStorage adapter.

Необходимые операции:

```js
getCharacterFolders()
createCharacterFolder(name)
renameCharacterFolder(folderId, name)
deleteCharacterFolderAndCharacters(folderId)
getCharacterFolderId(characterId)
moveCharacterToFolder(characterId, folderId)
getRootCharactersList()
getCharactersInFolder(folderId)
```

### Облачная синхронизация

Облачная синхронизация должна включать:

- список каталогов;
- принадлежность персонажа к каталогу;
- удаление каталогов;
- удаление персонажей из удалённого каталога.

### Импорт и экспорт

- Экспорт отдельного персонажа не зависит от каталога.
- Импортированный персонаж по умолчанию попадает в корневой список.

---

## 11. Локализация

Необходимые пользовательские строки:

| RU | EN |
|---|---|
| Каталоги персонажей | Character folders |
| Создать каталог | Create folder |
| Название каталога | Folder name |
| Персонажей: {{count}} | Characters: {{count}} |
| Вернуть в список персонажей | Move to character list |
| Удалить каталог? | Delete folder? |
| Удалить каталог и персонажей | Delete folder and characters |
| Отмена | Cancel |
| Создать | Create |

---

## 12. Совместимость

Для существующих пользователей:

- автоматически не создаются каталоги;
- все существующие персонажи считаются находящимися в корневом списке;
- при выключенной настройке старый сценарий работы с персонажами не меняется;
- существующие каталоги не скрываются при выключении настройки.

---

## 13. Критерии готовности

1. Настройка сохраняется между запусками.
2. При выключенной настройке существующие каталоги видны, но создать новый нельзя.
3. При включённой настройке доступна третья action-ячейка «Создать каталог».
4. Каталог нельзя создать без названия.
5. Новый каталог появляется в следующей ячейке сетки.
6. Каталог показывает актуальное количество персонажей.
7. Нажатие на каталог открывает его отдельный экран.
8. Drag начинается только с `arrow-all`.
9. Drop на каталог переносит персонажа.
10. Drop мимо допустимой зоны отменяет перенос.
11. Персонажа можно вернуть в корневой список.
12. Удаление каталога требует подтверждения.
13. Подтверждённое удаление удаляет каталог и персонажей внутри.
14. Каталоги и принадлежность персонажей сохраняются после перезапуска.
15. Каталоги и принадлежность синхронизируются через облако.
16. Все новые строки доступны в RU и EN.
