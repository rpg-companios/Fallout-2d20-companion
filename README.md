# Positronium — движок настольных ролевых игр

Движок для менеджера персонажей: хранение, редактирование, инвентарь,
облачная синхронизация и правила конкретной системы. Сам движок не содержит
ни одной игровой системы — сеттинг приходит отдельным пакетом `.trpg`,
который ставится по ссылке или файлом и дальше обновляется сам.

- Мобильное приложение: React Native + Expo (`app.json`, `eas.json`).
- Веб-сборка: `npm run build` (`expo export --platform web`).
- Лицензия: AGPL-3.0 (см. `LICENSE`, `NOTICE`).

## Скачать

| что | где |
| --- | --- |
| Android, последняя версия (APK) | <https://github.com/rpg-companios/ttrpg-engine/releases/latest/download/positronium.apk> |
| Все версии, состав и размер | <https://github.com/rpg-companios/ttrpg-engine/releases> |
| Веб-версия (PWA) | собирается `npm run build` и раздаётся с вашего хостинга |

Ссылка на APK постоянная: имя файла в релизе всегда `positronium.apk`, меняется
только тег `engine-v<версия>`. Поэтому адрес можно сохранить в закладки и
передавать людям — он не сломается со следующим релизом.

Установленный APK сам проверяет обновления: при запуске (и кнопкой
«Проверить обновления» в окне «О приложении») он читает `app-release.json`
движка и показывает окно «Доступна новая версия» со ссылкой на APK. В PWA
та же кнопка проверяет и обновляет страницу, а о новом веб-релизе сообщает
окно «Что нового». Правки только в JS доезжают ещё быстрее — по OTA
(`expo-updates`), без переустановки приложения.

## Что умеет без сеттинга

Приложение запускается и работает как менеджер персонажей: каталоги, папки,
импорт/экспорт, облачная синхронизация, настройки. Экранов и правил Fallout
нет, пока не установлен пакет сеттинга — это нормальное состояние чистого
движка, а не ошибка.

## Установка сеттинга

Движок не знает ни одного адреса заранее и ничего не предлагает поставить.

**По ссылке.** Настройки → настройки сеттинга → поле «Ссылка на репозиторий
или файл `.trpg`» → «Установить по ссылке». Понимаются `owner/repo`,
`https://github.com/owner/repo`, ссылка на `release.json` и прямая ссылка на
архив. Ссылка на репозиторий запоминается, и при запуске приложение проверяет
`release.json` этого источника (размер и sha256 проверяются).

**Файлом.** Настройки → настройки сеттинга → «Импортировать пакет `.trpg`» →
выбрать файл → «Установить» → выбрать сеттинг.

Официальный сеттинг Fallout 2d20: [rpg-companios/positronium-game-settings](https://github.com/rpg-companios/positronium-game-settings).

## Разработка

Нужны Node.js 18+ и npm.

```sh
npm install
npm start          # Metro: QR-код для Expo Go или устройство
npm run web        # запуск в браузере
npm run typecheck  # tsc --noEmit
```

Сборка веб-версии:

```sh
npm run build      # expo export --platform web → dist/
npm run serve      # раздать собранное на :5000 (npx serve, ставится на лету)
```

## Сборка APK

### Вариант 1 — EAS Build (облако, без Android SDK)

Нужен аккаунт Expo (бесплатный тариф подходит) и интернет.

```sh
npm install
npx eas-cli login
npm run apk
```

`npm run apk` — профиль `preview`: собирается **APK** (`buildType: apk`,
`distribution: internal`), в конце EAS даёт ссылку на скачивание. Первый
запуск спросит про Android keystore — согласитесь, EAS сгенерирует его сам
и запомнит в проекте.

Для Google Play нужен AAB:

```sh
npm run aab        # профиль production: app-bundle + autoIncrement
```

### Вариант 2 — локально (Gradle)

Нужны JDK 17 и Android SDK (`ANDROID_HOME`).

```sh
npm install
npm run apk:local
# android/app/build/outputs/apk/release/app-release.apk
```

`android/` и `ios/` генерируются заново (`expo prebuild`) и в git не
коммитятся.

## Релизы

Релиз движка — тег `engine-v<версия>` и GitHub Release с собранным APK
(и AAB, если он есть). Версия одна на всё приложение: `expo.version` в
`app.json` и `ENGINE_VERSION` в `src/engine/version.js` обязаны совпадать —
это закреплено тестом.

Текст релиза берётся из верхней секции `release-notes/engine.md`:

```markdown
## 1.0.1 — Что нового
Одна-две строки для игрока.
```

Выпуск (из совмещённого репозитория, откуда идёт публикация):

```sh
./scripts/publish-engine.sh --release --asset ~/Downloads/positronium-1.0.0.apk
```

Релиз требует APK: по нему собирается постоянная ссылка и `app-release.json`
(индекс обновлений для приложения). Файл на диске может называться как угодно —
в релиз он попадает как `positronium.apk`.

Публикация также пишет в корень репозитория движка `app-release.json` — его
читают APK и PWA. Обычный `publish-engine.sh` без `--release` файл не трогает.

OTA-обновление (только JS, без новой сборки; нативные изменения требуют
`npm run apk`):

```sh
npm run ota -- --message "Что изменилось"
```

## Структура

| путь | что там |
| --- | --- |
| `App.js`, `index.js` | точка входа приложения |
| `components/` | экраны и модальные окна |
| `db/` | хранилище: SQLite, веб-адаптер, сиды каталога |
| `domain/` | правила и вычисления, общие для всех систем |
| `src/engine/settings/` | контракт сеттингов: установка, активация, обновления |
| `src/engine/settings/settingRuntimeHost.js` | модули, которые движок отдаёт пакету (`engine:<id>`) |
| `i18n/` | локализация интерфейса (ru-RU, en-EN) |
| `docs/` | документация: архитектура, схема БД, отладка, сборка |
| `setting-contract.md` | формат `.trpg`, манифест, жизненный цикл пакета |

## Контракт с сеттингом

Пакет `.trpg` — это папка сеттинга с `manifest.json`, данными, переводами,
экранами и собранным `runtime/setting.cjs`. Код пакета не копирует движок:
он обращается к нему только через идентификаторы `engine:<id>`, а движок
отдаёт объявленный список модулей из `settingRuntimeHost.js`. Если пакет
просит необъявленный модуль, установка/сборка сообщает об этом явно.
Подробности — `setting-contract.md`.
